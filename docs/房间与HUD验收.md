# 房间与 HUD 展示修复

## 定位与改动

| 项目 | 原因 | 修改位置与结果 |
| --- | --- | --- |
| 创建后不全屏 | `app.js` 的创建按钮未调用全屏；`orientation.js` 只在开局/返回牌桌尝试，且跳过 PC。 | 新增 `src/ui/fullscreen.js`，全屏独立跟随房间会话。创建/加入的 click 同步链先请求 `document.documentElement.requestFullscreen()`，再等待网络；失败建房或离房退出。方向模块只管理开局横屏和方向锁。 |
| 房间码、余牌不齐 | 房间码混在说明文字，余牌单独使用比例字体；六位房间码另有字距和补偿 padding。 | `index.html` 把 HUD 房间码与余牌放在同一排；`styles.css`、`rooms.css`、`landscape.css` 统一等宽字体、tabular-nums、字号、字重、颜色、行高、基线及标签间距。房间码固定六位、余牌固定三位补零，房间面板复用数字样式。 |
| 手牌偏移 | 有副露时 `justify-content:flex-end`，副露还挤占暗手的 flex 空间；整个手牌区本身也偏离桌心。 | `landscape.css` 将暗手独立居中于牌桌；副露绝对定位在左侧，并在左右对称预留宽度。暗手 1–14 张不换行，牌少不放大，牌多按容器收窄；单张摸牌取消外侧空白。牌节点复用及原有选牌/出牌交互保留。 |

本轮未修改引擎、规则、发牌、判胡、网络协议或服务器业务代码，未增加依赖。上一轮每家 36 格牌河、竖屏创建/等待、横屏对局和手机/PC 共用布局继续保留。

## 全屏能力与降级

- 支持全屏时，手机与 PC 都在首次创建/加入手势中请求根容器全屏，不增加确认弹窗或专门的第二次点击。
- 创建失败、离开房间、延迟完成的全屏请求都有清理；返回房间面板仍属于同一房间会话，因此保持全屏，同时恢复竖屏房间布局。
- 不支持或被拒绝时，页面使用 100dvh 与安全区布局并显示添加到主屏幕提示，不阻止房间操作。添加了移动网页及 iOS 主屏幕显示元信息。
- 刷新恢复会话时自动尝试全屏；若浏览器要求新的用户手势，则在下一次普通房间操作中重试。CSS 无法强制隐藏浏览器地址栏，原生全屏与主屏幕独立运行模式以浏览器能力为准。这是 Fullscreen API 的用户激活限制，不将视口模式冒充原生全屏。
