## 三、两个人怎么改才不打架

### 分支约定

| 分支 | 用途 |
|---|---|
| `main` | 始终是可部署状态，只有确认能跑才合并进来 |
| `feat/xxx` | 一个功能一个分支，例如 `feat/landscape-square` |
| `fix/xxx` | 修 bug，例如 `fix/meld-overlap` |

都是小改动、两个人节奏一致时，直接提交到 `main` 也可以；一旦要动 `engine.js` 这种核心文件，先开分支。

### 每人每天开工前

```bash
git pull --rebase
```

### 提交信息

一行说清做了什么：

```
横屏牌桌改为正方形，座位与操作区贴合桌边
修复有副露时手牌区遮挡自己座位卡
```

不要写"更新""修改""fix"，半年后没人看得懂。

### 冲突了怎么办

会冲突的文件通常只有这两类：

- `landscape.css` / `styles.css`：两人同时调同一个区域
- `engine.js`：规则改动

冲突时**先沟通再合并**，别自己闷头选一边——规则类冲突选错会直接改坏判胡。

## 四、部署权：只给一个人

`deploy/update.ps1` 里有你的服务器密钥路径和 IP，**部署只由你执行**：

```powershell
.\deploy\update.ps1
```

朋友改完代码 push 上来，你 `git pull` 之后确认没问题再部署。两个人都部署会互相覆盖线上版本，而且服务器内存里的房间会被重启清空。

## 六、朋友也想起一个本地环境时

```bash
tar -xzf kk-mahjong-source.tar.gz
cd kk-mahjong
npm start          # 打开 http://localhost:5173
npm test           # 跑规则测试
```

项目零依赖，不需要 `npm install`。浏览器 UI 测试需要本机已有 Playwright，属于可选项。
