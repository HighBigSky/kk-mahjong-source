# 牌与桌面的接触关系

本轮基线：cad0e12。只改绘制，保留所有牌框、牌面图案、坐标、朝向、层级、圆角、间距和点击范围。

## 一盏右侧灯

场景继续使用右侧略偏前上方的灯。普通接触暗区的中心相对实牌中心向左移动实牌短边的4.5%，向近端移动1.125%；衰减范围同样按实牌宽度推导。强度统一配置：本家0.52，副露0.38，牌河0.32，暗手0.36，牌墙0.46；骰子0.72，短投影长度为骰子宽度的8.5%。

## 绘制与边界

- 牌内倒角、顶部/侧面与两层内影沿用原模型，不添加普通态外阴影。
- 在现有牌河、手牌、暗手容器、副露组和四段牌墙的背景上画短径向接触暗区，背景始终在实牌以下；没有第二层牌面、装饰覆盖层或新持久DOM。
- 布局器落位后复用现有投影测量，把实际屏幕牌框还原到各自牌区平面。static暗手容器先还原相对offsetParent的原点，不能把暗影画到别处。左右旋转牌河的接触影在桌面平面内直接朝左，不随牌字旋转。
- 相邻牌的暗区矩形止于两实牌之间的中线，并各退1/64px；足迹不重叠，缝隙内的深色不会相加。图案、牌背和侧面绘制在容器背景上方。
- 仍有实牌的连续墙墩合为一段，根部另加渐变暗缝及微高光。根部渐变连续穿过同段内的墩缝；空墩和空墙不留下幽灵影，不凭空连接原布局中没有牌的间隔。
- 骰子保留一层内凹材质影与一层朝左短影；按3倍模糊半径加扩展的保守范围核对，仍在原中控面板内。

只使用渐变与阴影，不新增图片、滤镜、DOM结构或依赖。每个牌绘制层与骰子的box-shadow最多两层。背景变量仅在实际值变化时写入，不增加动画或每帧循环。按区域缓存节点身份、牌序、格位、交互状态、矩形、舞台尺寸与光照；重复快照不再测量投影，单次出牌仅更新相关区域。容器渐变列表不继承到单牌，避免重复序列化和飞牌材质负担。

## 验证

运行 `node tests/ui-contact-shadows.mjs`，对比640×360、844×390、1280×720、1920×1080四档；牌河0/1/9/27/36张、完整四边牌墙和空墙。逐项比较DOM几何和SVG源，解析真实计算渐变的中心、矩形边界与衰减，检查旋转补偿、阴影层数、相邻暗区不重叠、空墙清理、骰子边界与全局backdrop-filter。测试只读取DOM和计算样式、解析渐变，不生成截图，也不宣称做了像素取样。
