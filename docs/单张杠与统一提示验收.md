# 单张杠与统一提示验收

本次修改集中在手牌交互、提示和用户补充确认的结算口径。不新增运行依赖。

| 文件 | 修改 |

| `app.js` | 300ms 特殊牌双击、取消选中态、420ms 最短表现锁与网络忙锁、单一提示状态、建议高亮和二次确认；保留普通牌出牌及普通四张杠入口。 |

## 已确认计分

底分为 10。红中杠、痞子杠由其余三家各付 10；赖子杠各付 20。开杠即时入账，荒庄保留。
补牌自摸额外加 10，其他原番型分值保留。屁胡自摸三家各付一份，接胡放铳一家付一份；大胡三家各付一份。
同牌身份按皮子 > 红中 > 癞子取唯一入口。杠的已经入账分数只汇总进整局净分，不在胡牌/荒庄时重复加减。

## 自动验收与复核步骤

环境：Windows Edge 155，无头浏览器；鼠标与触屏模拟分别运行。640×360、844×390、1280×720、1920×1080。专项牌例通过测试房间注入，136 张实牌守恒，操作通过真实 HTTP/SSE 完成，不是宣称自然随机发牌复现。

- [x] 1. 暗手放 1 张红中，单击只选中，300ms 内再次点击：红中杠、横放与标签、墙尾补牌；四个座位分别核对三家各付 10。
- [x] 2. 分别双击皮子/癞子，核对痞子杠/赖子杠与三家各付 10/20；手里同时有两者可以分别声明。
- [x] 3. 普通牌两次点击仍正常出牌，牌河增加一张。
- [x] 4. 连续点击与重放同一 requestId：一次请求只开一次杠、扣一次分、补一次牌；旧版本新请求仍由服务端拒绝。
- [x] 5. 测试构造皮子=红中、癞子=红中局：分别只允许痞子杠/红中杠，均 1 倍，不重复记录。保留现有正常发牌时红中候选换白板的规则。
- [x] 6. 14 张或碰后 11 张待打，提示在手牌左侧顶部显示“打 X → 听 Y（逐张余量与总数）”，不遮手牌与操作区。
- [x] 7. 13 张已听且别家回合显示“已听”；别家回合未听隐藏。当前第四张可接胡时标“0张，仅接胡”，不伪称墙中还有牌。
- [x] 8. 无候选、开局骰子、请求/特殊杠表现期、结束/荒庄隐藏；手牌、公开副露、弃牌改变时缓存失效重新计算。
- [x] 9. 点击提示只高亮，二次点按钮或建议牌才提交出牌；候选选择框最多 5 条，只切换建议，不自动出牌。
- [x] 10. 删除旧听胡按钮、弹窗和对应样式，只有统一提示入口。

运行 `npm test`、`npm run test:ui:assist`、`node tests/ui-touch-zoom.mjs`、`npm run test:ui:layout`、`npm run test:ui:hud`、`npm run test:ui`。
`npm test` 含 200 局冻结规则对照、三类杠四座位付款、荒庄保分、屁胡/四种大胡付款、杠上开花与防重复结算。代表性 14 张冷计算本轮并行回归实测最高约 24ms；此数据不代表所有旧手机的硬件耗时保证。

## 边界与已知风险

- 未见张数 = 4 − 自己暗手 − 所有公开实牌；包含别人暗手，不读取隐藏牌墙或对手手牌，不能称作保证可摸张数。自己的副露、翻皮和正在响应的弃牌均只计一次。
- 很长的听牌列表在左侧固定区域内部滚动，可通过候选框或按钮 title 查看完整文字；区域不挤动手牌。
- iOS/Android 真机尚未实测；触屏结果来自 Edge 模拟。
- 旧 `ui-interaction-polish.mjs` 的 640×360 顶部玩家与连接标签不重叠断言失败。对本次修改前的 `5d93726` 独立导出运行同一旧测试，得到相同失败；本次保留该原有顶栏问题，没有将它描述成测试通过。专项提示、布局、全屏与手牌居中另有独立验收。
- 本次含服务端修改，上线需要重启；部署前检查在线连接、备份并在没有在线连接时更新。内存中的旧房间在重启后需要重新创建。
