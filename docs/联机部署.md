# KK麻将好友房部署

此版本由同一台 Node.js 服务器保存房间和牌局。真人通过房间码加入，对局进行时各自浏览器只接收自己的暗手和公开桌面；有人胡牌后，服务器向本房间所有玩家公开四家的剩余手牌，下一局恢复暗手隔离，流局仍保持其他人的暗手隐藏。房主也可向空位添加人机，支持 1–4 位真人搭配 0–3 位人机，共四家对局。摸牌、合法动作、抢牌优先级、计分及人机决策统一在服务器执行。

## 本机启动

需要 Node.js 18 或更新版本，无须安装第三方依赖。

```powershell
cd D:\麻将
npm start
```

本机打开 `http://localhost:5173`。一人创建房间并分享邀请链接或房间码，好友进入同一网站加入。开局前，房主可在房间中向空位添加或移除人机，也可留空位等待好友。座位已满时，先移除人机再邀请真人入座。四个座位到齐、真人分别准备后，由房主开始；人机自动准备。

创建、加入房间前为竖屏入口，进入房间后立即使用横屏等待与对局页面；离开房间后恢复竖屏。手机支持时尝试原生全屏和横屏锁定，浏览器不支持时自动旋转横屏界面，保持全部按钮可操作。部署须同时包含 `landscape.css` 和 `src/ui/orientation.js`，Dockerfile 已纳入这两个文件。

人机使用引擎已有策略，约每 650 毫秒执行一次操作，不改变规则或计分。对局中不能添加、移除人机或替换真人；真人断线仍会暂停整桌，人机不会接管掉线真人。

本机可用四个独立浏览器上下文验证四个座位；同一标签页刷新会恢复自己的座位，不会新占一个座位。

`localhost` 只代表访问者自己的设备；把 `http://localhost:5173` 发给异地好友无法访问。房间码只在同一个服务器内有效。

## 异地异网访问

把项目部署到一台具有公网访问地址、可常驻运行 Node.js 的服务器。也可以使用支持常驻 Web 服务和 SSE 的托管平台。所有玩家访问这个公网地址，服务器默认监听 `0.0.0.0`。

| 环境变量 | 默认值 | 部署设置 |
|---|---|---|
| `PORT` | `5173` | 平台可注入其分配的监听端口。 |
| `HOST` | `0.0.0.0` | 容器和托管平台保持此值；直接在主机运行、仅供本机代理时可设为 `127.0.0.1`。 |
| `PUBLIC_ORIGIN` | 空 | 设为用户访问的实际 HTTPS 源，例如 `https://mahjong.example.com`，不含路径和查询参数，用于校验同源动作请求。 |

文中的 `mahjong.example.com` 是示例域名，并未部署；需要替换成自己的域名。邀请链接从玩家当前访问的网址生成，`PUBLIC_ORIGIN` 不会把本地网址变成公网网址。

推荐使用域名和 HTTPS，代理到本机 `5173`。如果使用反向代理，必须关闭 SSE 响应缓冲、缓存，并允许长连接；不要使用仅托管静态网页的空间。服务器与反向代理应启用进程自动重启。

Nginx 示例，域名、证书路径需要替换成自己的实际值：

```nginx
server {
    listen 443 ssl;
    server_name mahjong.example.com;
    ssl_certificate /etc/letsencrypt/live/mahjong.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/mahjong.example.com/privkey.pem;
    # SSE 地址包含临时身份令牌；本示例不把请求地址写入访问日志。
    access_log off;

    location / {
        proxy_pass http://127.0.0.1:5173;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Connection "";
        proxy_buffering off;
        proxy_cache off;
        proxy_read_timeout 3600s;
    }
}
```

服务器只需向公网开放 HTTPS 端口；Node 端口可仅供反向代理访问。若暂时直接访问 `http://公网IP:5173`，还需允许云安全组和服务器防火墙的 `5173/TCP` 入站。HTTPS 更适合浏览器复制邀请链接等功能。

## Docker

镜像构建不执行 `npm install`，运行时也不下载包。首次构建需要能获取官方 Node.js 基础镜像。

```sh
docker build -t kk-mahjong .
docker run -d --name kk-mahjong --restart unless-stopped -p 127.0.0.1:5173:5173 -e PUBLIC_ORIGIN=https://mahjong.example.com kk-mahjong
```

此命令将 Node 仅映射到本机，搭配上面的 HTTPS 代理。如果选择公网端口直连，把映射改为 `-p 5173:5173`，并配置对应防火墙。

Docker 镜像仅复制运行所需页面、脚本、样式和素材，不包含测试、截图、文档或本地配置。容器使用普通 `node` 用户，并通过 Node 内置 `fetch` 每 30 秒检查 `/healthz`，不额外安装 curl 或健康检查包。查看运行状态：

```sh
docker ps --filter name=kk-mahjong
docker logs --tail 50 kk-mahjong
docker inspect --format='{{.State.Health.Status}}' kk-mahjong
```

支持 Dockerfile 的托管平台也可使用：将构建上下文设为项目根目录、Dockerfile 设为根目录 `Dockerfile`，实例数量设为 1，健康检查路径设为 `/healthz`，启用平台提供的 HTTPS 并把 `PUBLIC_ORIGIN` 设为该实际网址。确认平台支持长时间 SSE 连接、关闭代理缓冲，并避免实例休眠。此项目不适合纯静态托管或每次请求创建新实例的无状态函数平台。

不使用 Docker 时，在服务器设置相同环境变量后直接运行 `node server.js`，交由系统服务或平台管理进程。两种方式均无构建和依赖安装步骤。

## 运行约定

- 当前房间、身份令牌和积分保存在服务器内存，服务器重启或实例替换后房间消失，玩家需要重新建房。不应在未结束的牌局中发布更新。
- 使用单实例部署；负载均衡到多个独立进程会把同一房间分散到不同内存。水平扩容需先增加共享房间存储和跨实例消息，本版本未实现。
- 接口按直接连接的 IP 限流；经反向代理时，同一代理后的玩家共享额度（每分钟 1200 次接口请求、30 次建房、240 次加入）。当前四人好友房可正常使用；扩大到多人多房前，应在可信代理层配置真实客户端 IP 限流。服务器不会直接信任浏览器可伪造的 `X-Forwarded-For`。
- 刷新或短时断网后，原标签页可凭 sessionStorage 保存的身份恢复原座位。关闭标签页、清除站点数据、换浏览器或换设备不会自动找回座位；不要把浏览器中的身份令牌分享给别人。
- 真人掉线被确认后整桌暂停，包括人机操作，重新连接恢复；等待和掉线期间不会让人机接管真人，不会替真人自动选择吃碰杠胡。个人打开弹窗不会暂停整桌。
- 只有房主可在开局前管理人机。每桌至少保留一位真人，最多三位人机；人机自动准备，真人仍须各自准备。房间中的添加与移除请求由服务器校验权限和对局阶段。
- 房间码用于邀请进入空座位，并非账号密码。请只向本局好友分享。无账号、支付、持久化排行或旁观服务。
- 页面通过 SSE 接收状态、通过同源 HTTP 请求提交动作，无须配置 WebSocket 或 NAT 打洞。不同运营商与不同 Wi-Fi 不影响连接，只要都能访问同一个公网服务器。

## 验证

```sh
npm test
npm run test:online
npm run test:ui
node tests/ui-bots.mjs
npm run test:ui:wall
npm run test:ui:melds
npm run test:ui:rules
```

浏览器用例需要本机已经具备 Playwright 及可用浏览器，不属于运行游戏的依赖。四真人用例会创建临时 HTTP 服务器和四个独立浏览器上下文，验证创建、邀请、加入、准备、开局、状态同步和刷新恢复。`tests/ui-bots.mjs` 另外覆盖房主人机管理、真人与人机混合开局及服务器自动操作。`test:ui:wall` 覆盖骰子翻皮原位、真实摸补牌后逐张余牌同步、四边完整牌墙、公开位置同步、重复快照不重建皮子和四种尺寸下的无遮挡显示。

`npm test` 已包含房间接口测试，`test:online` 用于单独复查。旧的单机 UI 脚本未适配好友房入口，不能用来宣称当前联机界面验收通过。本地没有 Docker 时只能检查 Dockerfile 内容；不能把静态检查算作镜像构建或容器运行成功。

`test:ui:melds` 验证红中／皮子单张杠及吃碰杠牌组的真实点击、四人公开同步与暗手隔离，并覆盖四种尺寸下的最多公开牌和完整暗手布局。规则变更需要重启 Node 服务；请先结束当前牌局，重启后重新创建房间。

`test:ui:rules` 验证二五八将、开口屁胡最多一个癞子、未开口屁胡只能自摸不能接胡，以及七对、碰碰胡、将一色、风一色的豁免；四端实际胡牌同步，非法胡请求不能绕过服务端校验。

`test:ui:reveal` 验证胡牌后四家手牌同时亮出、刷新重连仍可查看、下一局恢复暗手隔离；进行中和流局不提前公开暗手。更新此功能后需重启 Node 服务，已有内存房间会失效。

`test:ui:notices` 验证四人同步的吃碰杠胡彩字提示。提示通过服务端公开状态确认后发布，响应等待和抢牌败选不误报；客户端按剩余时长显示，同一通知不因重连或重复快照续期，胡字保留到下一局。人机与真人使用同一通知路径。

发布后请再用手机蜂窝网络和另一处 Wi-Fi 的设备共同进入公网地址，完成好友加入、人机补位、真人准备、摸打、抢牌响应、刷新恢复和下一局。仅本机自动化无法证明你的域名、证书、云安全组和异地线路已正确配置。

本次代码交付包含可部署服务器；公网服务器、域名和托管账号需由实际部署环境提供，仓库中的本地地址不等于已上线地址。
