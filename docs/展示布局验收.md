# 展示与布局修复验收

本报告记录提交 `5fa325c` 的验收。后续全屏生命周期、数字排版和手牌居中更新见《房间与HUD验收》；原有满牌河与横竖屏约定继续保留。

## 1. 定位结论

| 问题 | 原位置 | 原因 |
| --- | --- | --- |
| 牌河显示不全 | `app.js` 的牌河渲染、`discardRiverTile()`；`landscape.css` 的 `.river` 网格 | JS 只保留上下最近 12 张、左右最近 6 张；CSS 使用固定桌面单位的牌宽与行高，多份旧样式继续覆盖位置与容量。 |
| 等待页横屏、竖拿对局被旋转 | `src/ui/orientation.js`、`app.js` 的 `roomChanged()` | 按是否加入房间启用横屏，再由窗口宽高决定 90° 旋转与 `is-wide` 分支，没有区分等待和对局。 |
| 冗余适配 | `landscape.css`、`styles.css`、`rooms.css`、`seats-layout.css`、`wall-layout.css` 及旧测试/文档 | 宽高阈值、矮屏补丁、旋转舞台、旋转弹窗、横屏等待页和多层旧牌河几何叠加。代码中没有独立 UA 或设备类型模块需要保留。 |

## 2. 改动清单

| 文件 | 改动与删除项 |
| --- | --- |
| `app.js` | 删除 12/6 张截断与索引偏移，全部弃牌按原顺序显示。原位放大最多 1.5 倍，按实际邻牌、牌墙、头像和操作区限制上限；缩回使用实际放大比例。删除竖屏旋转坐标换算。由房间状态与房间面板路由驱动展示；返回房间后收到结束或下一局快照不会强行切回。 |
| `landscape.css`、`src/ui/river-layout.js` | 每家固定 27 格，上下 9×3、左右 3×9，从桌心侧、所属玩家左手边开始，逐行向玩家方向排列；容量与桌内区域位置集中配置。保留双倍精度绘制、原有牌体、相机与桌框。 |
| `src/ui/orientation.js` | 仅 `dealing/playing/ended` 且未返回房间面板时启用横屏对局。粗指针手机在开局尝试全屏/锁横屏，竖拿时显示引导；PC 不锁屏、不旋转。不再按窗口尺寸生成布局变量或切换版式。 |
| `index.html` | 增加「请横屏使用」引导层及返回房间按钮。 |
| `styles.css`、`rooms.css` | 删除宽度阈值与矮屏补丁，删除旧牌河尺寸与位置覆盖；保留通用材质和控件外观。 |
| `seats-layout.css`、`wall-layout.css` | 删除旧竖屏牌河网格、位置与容量覆盖，保留座位、牌墙和副露的共同视觉。 |
| `tests/`、`package.json` | 重写方向验收，新增满牌/动画验收入口；现有展示用例改用手机横屏和 PC 分辨率，移除旋转坐标及 12/6 截断断言。直接删除已失效的三个单机竖屏布局测试。修正旧联机测试对重复 SSE、癞子杠和提示按钮的过时假设。 |
| `README.md`、设计规格、联机部署、历史报告 | 删除旧旋转、等待横屏、竖屏对局及过时测试命令，记录当前单一布局策略和容量。 |
| `engine.js` | 仅两处 `PlayerId` JSDoc 类型断言，修复原有类型检查错误。去掉新增注释后与修改前文件逐字一致，没有执行逻辑变化。 |

每家 27 格覆盖含吃碰跳家的单家留河保守上界。83／84 次摸打预算下的穷举推导见设计规格与 `tests/river-capacity.test.js`。释放旧 36 格中的一行后，牌河牌面可进一步等比放大，仍不使用固定像素。下方原验收记录中的 36 格为历史版本；当前以 27 格重复满河、最大副露、特殊杠及完整手牌、操作按钮与动画验收。

## 3. 自测结果

浏览器为本机 Edge 155.0.4283.62 无头模式。手机使用粗指针/触摸仿真；方向锁定成功、拒绝与 API 缺失均有明确模拟，未将这些结果表述为手机实机验证。

| 验收项 | 分辨率与设备 | 结果 |
| --- | --- | --- |
| 创建与等待竖屏 | 手机 360×640 | 创建、加入、等待、准备均保持竖屏；没有请求方向锁定。 |
| 开局与旋转引导 | 手机 360×640 → 640×360、844×390 | 开始后才进入横屏布局；竖拿显示引导，横置后关闭；两个横屏尺寸画布铺满。三种 API 情况全部通过。 |
