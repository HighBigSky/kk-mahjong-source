# 手机横屏轻透视牌桌

当前状态：牌桌保持上一版 1:1 方桌、46° 透视与扩大 10% 的尺寸。桌上四家的手牌、牌河、牌墙和副露均沿所属桌边对齐；左右牌区只做平面旋转，牌面仍为正常等比例矩形。同家手牌、副露、牌墙、牌河的中心沿桌边法线排齐，本家前墙校正 `.25` 个 table-unit 的居中偏差。

按最后确认的要求：牌区沿真实桌边方向摆放，但不恢复导致牌面压扁的 3D 倾斜。此次不改规则、发牌、计分、协议，也不新增依赖或设备分支。手机和 PC 共用现有横屏布局，建房与等待页继续竖屏。

## 关键参数

项目使用 CSS 3D，没有米制场景与真实摄像机，因此不虚构厘米位置。以下为可直接调节并实测的投影参数。W、H 均指扣除安全区后的横屏舞台宽高；PC 高窗口沿用居中的 16:9 舞台。

桌框没有 `scaleX` 压缩，也未缩放整张屏幕。方框素材仍为 `1000×1000`，保留原木纹和暖色材质。三家牌区使用浏览器真实投影的逆映射，消除斜边及压扁；删除原左右牌河 `1.44` 纵向补偿，每家仍有 36 个紧密格位，朝向及时间顺序不变。

三条他家牌墙沿用展示容器，136 个真实 DOM 槽位及原始顺序保留。投影按尺寸、牌组尺寸及所属基准线缓存。另三家的出牌放大/缩回同步使用「所属桌边角度 + 原牌面朝向」，尺寸使用牌河组的真实等比系数；本家动画继续使用原桌面平面。桌面相机、中央指示区、头像、提示与操作区、灯光和环境不变。

## 文件改动

- `src/ui/flat-opponents.js`：按桌框投影四角计算各家的桌边角度与法线，排列手牌/副露、牌墙和牌河。
- `landscape.css`：仅将本家前墙起点从 `14` 校正为 `13.75`，对齐桌面中心。
- `app.js`：出牌放大/缩回同步读取所属牌河的桌边角度和等比尺寸。
- `src/ui/opening-deal.js`：沿桌边方向落牌，使用真实牌身尺寸与旋转角，不将牌拉伸到外接包围盒；本家发牌轨迹沿用原样。
- `tests/ui-seated-view.mjs`：检测四家牌区与对应桌边平行、同家中心线对齐、牌身矩形及正常比例；保留 136 个槽位顺序、满牌和真实输入验收。
- `tests/ui-opening-deal.mjs`：比对开局飞牌末帧和真实手牌四角。
- 本文件更新当前参数；游戏引擎、服务器、网络模块、素材不变。

关键样式位于 `landscape.css` 的坐席视角区。桌面背景投影仍由 `.table` 提供，他家牌组通过逆映射抵消倾斜；文字与本家手牌为舞台上的兄弟节点。CSS 与实际 DOM 共用浏览器命中区域，没有另造点击坐标。

## 观感变化

原先他家牌区沿屏幕横竖轴摆放，和左右斜桌沿方向不一致；现在牌列沿各自桌边排齐，手牌/副露、牌墙和牌河形成同家的一组布局。牌面只平面旋转、不变形；自己的手牌和牌河保持原位，前墙仅作微小居中校正，其他界面保持原样。

## 验证

- Edge 155 浏览器，触屏模拟：640×360（16:9）、844×390 与 780×360（约 19.5:9）、800×360（20:9）；PC 1920×1080。
- 本轮验收：15 个满牌/最多副露场景、20 个手牌数量场景、20 个实际 HTTP/SSE 单击/双击场景；手牌 1/2/7/14 张平直、居中、不换行；普通牌与三种特殊牌的动作请求正确且只发一次。四家牌区相对桌沿方向的归一化叉积误差小于 `.002`，同家中心线误差小于 `1.2px`，本家前墙中心误差小于 `.8px`；真实牌边长比误差小于 2%，四角仍为直角，不以旋转后的包围盒判定是否变形。四家实牌不得越出绒布安全区；自己的手牌、牌河、HUD、相机和桌框投影逐像素一致。

## 手测与边界

1. 手机竖屏创建房间，开局后横置；确认等待页仍竖屏，对局只有一套横屏布局。
2. 检查桌沿有轻微收窄、木边厚度，自己的牌为平直排布。切换 16:9 与 20:9，牌面不能被拉伸。
3. 从手牌左、中、右分别单击选中、再次点击普通牌出牌；特殊牌在 300ms 内双击开杠。操作后提示面板与手牌中心不得横移。
4. 牌数减少并出现碰杠副露时，检查剩余手牌仍居中；点击提示先高亮、再次点击确认。
5. 牌河满牌时检查四区都完整可见；最新弃牌应在原位置放大，下一家操作后原位缩回。
6. 检查方向、杠型、翻皮墩号、摸补文字为正向清晰文字；操作按钮可正常点击。

实体 iOS/Android 设备尚未逐机测试；本轮使用 Edge 触屏模拟。牌、按钮、玩家信息均须完整可见。
