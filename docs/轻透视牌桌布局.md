# 手机横屏轻透视牌桌

当前状态：牌桌保持上一版 1:1 方桌、46° 透视与扩大 10% 的尺寸，不再改动。除自己之外三家的手牌、牌河、牌墙和吃碰杠副露改为正常平面，牌面为等比例矩形，横竖牌列保持笔直；自己的手牌、副露、牌河、前墙与其他 HUD 保持原样。

按最后确认的要求：牌桌沿用已有视角，另外三家的牌区不再跟随桌面倾斜。此次不改规则、发牌、计分、协议，也不新增依赖或设备分支。手机和 PC 共用现有横屏布局，建房与等待页继续竖屏。

## 关键参数

项目使用 CSS 3D，没有米制场景与真实摄像机，因此不虚构厘米位置。以下为可直接调节并实测的投影参数。W、H 均指扣除安全区后的横屏舞台宽高；PC 高窗口沿用居中的 16:9 舞台。

| 参数 | 最终值 |
| --- | --- |
| 桌面倾斜 | `rotateX(46deg)`，对应约 44° 向下观察，较首版强第一人称方案更轻 |
| 透视焦距 | `perspective(2T)`，随桌面同步缩放，保持投影形状与牌面比例 |
| 投影中心 | `(50%W, .98H - .4236T)`，按近沿定位反推 |
| 逻辑内容区 | 进深 `T = min(.64W, 1.35H)`，宽 `L = 7T/9`；统一容器约束，无设备分支 |
| 实物木框 | 宽、深均为 `1.10T`，源宽深比 `1:1`；独立变量 `--table-frame-size` 只用于桌框和绒布，保留原 `--table-surface-width` 供牌区定位；方框素材仍使用 `contain` 等比显示 |
| 桌面定位 | `left: 50%W - L/2; top: .98H - .9236T`，变换原点居中 |
| 他家正常视角 | 浏览器测量原牌组四角并反算投影，抵消桌面倾斜后映射为正向矩形；中心保持原投影中心，组内统一等比缩放，不逐牌压扁或拉伸 |
| 他家牌区尺寸 | 对家牌河按原横向尺度的 `.70`、左右牌河 `.90`、三家手牌与牌墙 `.72` 等比显示，为恢复正常高度保留空间；不改变本家的牌尺寸 |
| 投影后比例 | 主体（远近沿平均宽度）约 `71%W～75%W`；近沿约 `85%W～90%W`，没有横向拉伸 |
| 桌面上/下边缘 | 远沿锚点与原来一致；近端绒布延展至完整本家手牌下方，允许近端木框在画面底部以外，所有实牌完整可见 |
| 本家手牌 | 不旋转、不扇形、不受桌面透视；宽 `.66W`，中心 `50%W`，底边 `98.5%H` |
| 前方牌墙 | 仍为 17 墩，单牌宽 `2.5L/70`、高 `3.5L/70`，由左侧 `14L/70` 开始紧密排列；等比收拢以避让最多副露，本家副露保持原位 |
| 对家头像 | 左边缘 `50%W + .27T`；上边缘 `max(.02H, .90H - .7179T)`，位于对家牌列右上方，避免扩大后的牌列遮挡头像 |
| 对家暗手/副露 | 上边缘 `.08T`，整组居中；原先 `1.1L/70` 太靠近木框，已内移至绒布安全区 |
| 对家牌墙 | 上边缘 `.15T`，位于对家手牌与牌河之间，原有 17 墩与顺序保留 |
| 左右暗手 | 以桌面中心向两侧 `.425T` 定位；容器上/下边界为 `.22T` / `.82T`，牌列居中，暗牌只显示牌背 |
| 左右牌墙 | 以桌面中心向两侧 `.35T` 定位；从 `.22T` 起按 `.032T` 步长摆放 17 墩，分别正序/倒序，牌面比例不变 |
| 上/下牌河 | 宽 `.38L`、水平居中；上边缘 `.22T` / `.58T`，高约 `.1714T`；9×4 紧密填格，牌面由格子宽高共同约束 |
| 左/右牌河 | 两侧向内 `8L/70`；上边缘 `.32T`，高 `.371T`，宽 `13L/70`；4×9 紧密填格 |
| 中央骰子区 | 宽高 `14L/70`；水平居中，上边缘 `.40T`，与上下满牌牌河分开 |
| 操作与提示 | 操作区沿用原先屏幕坐标；「提示」入口仍在手牌左侧，胡牌卡片在手牌右上方，均不倾斜 |
| 回合与出牌文字 | 位于左侧信息带，左边缘 `.02W`、宽 `.20W`，上边缘 `.20H` / `.25H`，避开内移后的对家牌墙 |

桌框没有 `scaleX` 压缩，也未缩放整张屏幕。方框素材仍为 `1000×1000`，保留原木纹和暖色材质。三家牌区使用浏览器真实投影的逆映射，消除斜边及压扁；删除原左右牌河 `1.44` 纵向补偿，每家仍有 36 个紧密格位，朝向及时间顺序不变。

三条他家牌墙按原位置增加展示容器，136 个真实 DOM 槽位及原始顺序保留。投影只在初次展示、尺寸或牌组尺寸变化时计算并缓存。另三家的出牌放大/缩回使用屏幕平面匹配目标实牌的尺寸和朝向，本家的动画继续使用原桌面平面。桌面相机、中央指示区、头像、提示与操作区、灯光和环境不变。

## 文件改动

- `src/ui/flat-opponents.js`：新增展示投影辅助模块，抵消他家牌区倾斜并缓存尺寸，保留原节点与槽位。
- `landscape.css`：正常视角牌组与牌墙容器样式，移除他家侧河纵向拉伸补偿；桌框和自己的牌区规则不变。
- `app.js`：在渲染和尺寸变化时更新展示投影；他家出牌放大/缩回匹配新平面。
- `tests/ui-seated-view.mjs`：检测三家牌的屏幕四角为正向矩形、长宽比一致、全部 136 个牌墙槽位顺序不变；对比自己的牌区、HUD 和桌框坐标。
- 本文件更新当前参数；游戏引擎、服务器、网络模块、素材不变。

关键样式位于 `landscape.css` 的坐席视角区。桌面背景投影仍由 `.table` 提供，他家牌组通过逆映射抵消倾斜；文字与本家手牌为舞台上的兄弟节点。CSS 与实际 DOM 共用浏览器命中区域，没有另造点击坐标。

## 观感变化

原先三家牌面随桌面倾斜，左右牌列有斜边，牌面高度随远近改变；现在他家牌列为笔直的正常矩形，牌河及吃碰杠保持正常长宽比。只有原牌桌背景和本家桌上实物沿用既有透视，自己的手牌与其他界面保持原样。

## 验证

- Edge 155 浏览器，触屏模拟：640×360（16:9）、844×390 与 780×360（约 19.5:9）、800×360（20:9）；PC 1920×1080。
- 本轮验收：15 个满牌/最多副露场景、20 个手牌数量场景、20 个实际 HTTP/SSE 单击/双击场景；手牌 1/2/7/14 张平直、居中、不换行；普通牌与三种特殊牌的动作请求正确且只发一次；提示先高亮、再确认；画布聚焦后不横移。三家牌面屏幕四角必须横平竖直，长宽比误差小于 2%。包括本家在内的四家实牌不得越出绒布安全区；修改前后自己的牌区、HUD、相机和桌框投影逐像素一致。
- 旧牌河验收：24 个布局场景与 24 个出牌动画场景通过，144 张压力弃牌完整显示，无遮挡、裁剪或滚动，动画前后位置变化为 0。

- 本轮规则与网络 257 项单元测试、项目 TypeScript 检查通过；本轮 JavaScript 改动仅涉及 UI 展示。
- `git diff --check` 通过。

## 手测与边界

1. 手机竖屏创建房间，开局后横置；确认等待页仍竖屏，对局只有一套横屏布局。
2. 检查桌沿有轻微收窄、木边厚度，自己的牌为平直排布。切换 16:9 与 20:9，牌面不能被拉伸。
3. 从手牌左、中、右分别单击选中、再次点击普通牌出牌；特殊牌在 300ms 内双击开杠。操作后提示面板与手牌中心不得横移。
4. 牌数减少并出现碰杠副露时，检查剩余手牌仍居中；点击提示先高亮、再次点击确认。
5. 牌河满牌时检查四区都完整可见；最新弃牌应在原位置放大，下一家操作后原位缩回。
6. 检查方向、杠型、翻皮墩号、摸补文字为正向清晰文字；操作按钮可正常点击。

实体 iOS/Android 设备尚未逐机测试；本轮使用 Edge 触屏模拟。牌、按钮、玩家信息均须完整可见。
