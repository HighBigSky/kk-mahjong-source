# 手机横屏轻透视牌桌

按最后确认的要求：本家手牌保持平直、水平居中；只有牌桌与桌上实物带轻微坐席透视。此次不改规则、发牌、计分、协议，也不新增依赖或设备分支。手机和 PC 共用现有横屏布局，建房与等待页继续竖屏。

## 关键参数

项目使用 CSS 3D，没有米制场景与真实摄像机，因此不虚构厘米位置。以下为可直接调节并实测的投影参数。W、H 均指扣除安全区后的横屏舞台宽高；PC 高窗口沿用居中的 16:9 舞台。

| 参数 | 最终值 |
| --- | --- |
| 桌面倾斜 | `rotateX(46deg)`，对应约 44° 向下观察，较首版强第一人称方案更轻 |
| 透视焦距 | `perspective(1.8H)`，16:9～20:9 水平视场约 53°～63° |
| 投影中心 | `(50%W, 52%H)` |
| 逻辑桌面 | 宽 `L = .94H`，进深 `T = .90H` |
| 木框源宽 | `1.45H`；源宽/进深固定为约 `1.61`，宽屏不会横向拉伸 |
| 桌面定位 | `left: 50%W - L/2; top: .07H`，变换原点居中 |
| 投影后比例 | 近沿约 `99.4%W`（16:9）～`79.5%W`（20:9）；可见进深约 `64.6%H` |
| 桌面上/下边缘 | 约 `25.5%H` / `90.1%H`，下方保留木边厚度和阴影 |
| 本家手牌 | 不旋转、不扇形、不受桌面透视；宽 `.66W`，中心 `50%W`，底边 `98.5%H` |
| 对家头像 | 水平中心 `50%W`，上边缘 `13%H`，与桌上牌背分开 |
| 左右暗手 | 以桌面中心向两侧 `.415 × 木框源宽` 定位；侧转由 ±75° 调整至 ±50°，附加 -12° 俯角与象牙色倒角，暗牌保持只显示牌背 |
| 左右牌墙 | 以桌面中心向两侧 `.37 × 木框源宽` 定位；原有每边 17 墩与顺序保留 |
| 上/下牌河 | 桌内 `left:20%L; width:60%L`；上边缘约 `.147T` / `.60T`，高约 `.207T` |
| 左/右牌河 | 外侧距逻辑桌边 `.01L`；上边缘 `.371T`、高 `.371T`，宽 `11L/70` |
| 中央骰子区 | 宽高 `14L/70`；水平居中，上边缘 `.5T - 9.5T/70` |
| 操作与提示 | 沿用原先屏幕坐标；提示仍在手牌左侧、顶部对齐，按钮不倾斜 |

牌面宽高比例保持原有 5:7。左右牌河以刚性旋转抵消桌面俯角，不使用 scaleX/scaleY 拉伸；旋转后的屏幕宽高比实测约 1.40。牌河仍每家固定 36 格，由容器约束反推牌宽，出牌动画继续使用现有 `tablePoint()` 逆投影和原牌位，侧河放大与缩回也沿用相同牌面角度。

本次只优化侧家手牌角度/倒角、侧河牌面比例、桌面宽度及相应锚点。相机、桌面高度、本家手牌、外侧头像与操作区、颜色、材质、灯光及环境设置均沿用原版。

## 文件改动

- `landscape.css`：统一轻透视相机、桌面进深与边沿；分开控制牌宽与纵向间距；调整侧河和中央区域，确保满牌不相压；三家暗手竖立；暖光、暗绿绒布、木边厚度、环境柔化；舞台使用 `overflow:clip`，避免浏览器聚焦手牌时滚动画布。
- `app.js`：增加桌内文字的屏幕坐标镜像与避让，跟随实际实物锚点；保留原标签的读屏语义，镜像无交互；对静态更新期间旧 HTML 缺少镜像容器的情况作空值保护。本家手牌渲染与交互保持原样。
- `index.html`：增加一个 `aria-hidden`、不接收点击的文字容器。
- `tests/ui-seated-view.mjs`：增加横屏比例、满河、平直居中手牌、实际触屏/鼠标输入、提示确认与画布不滚动的浏览器验收。

关键样式位于 `landscape.css` 的坐席视角区。桌面实际变换仍只在 `.table` 上，文字与本家手牌为舞台上的兄弟节点。CSS 与实际 DOM 共用浏览器命中区域，没有另造点击坐标。

## 观感变化

之前为浅倾斜的平面棋盘，三家的暗手贴在桌面上，前沿较薄。现在桌沿近宽远窄，三家暗手竖起，木边有连续厚度和柔和投影，中心受暖光照亮。本家手牌仍为熟悉的平直排布，选牌仅按原方式上抬。

## 验证

- Edge 155 浏览器，触屏模拟：640×360（16:9）、844×390 与 780×360（约 19.5:9）、800×360（20:9）；PC 1920×1080。
- 新验收：15 个满牌场景、20 个手牌数量场景、20 个实际 HTTP/SSE 单击/双击场景通过；手牌 1/2/7/14 张平直、居中、不换行；普通牌与三种特殊牌的动作请求正确且只发一次；提示先高亮、再确认；画布聚焦后不横移。五种分辨率下桌面源宽高比固定约 1.61，左右侧河静止及放大牌面的屏幕宽高比均约 1.40（旋转后的 5:7），无非等比拉伸。
- 旧牌河验收：24 个布局场景与 24 个出牌动画场景通过，144 张压力弃牌完整显示，无遮挡、裁剪或滚动，动画前后位置变化为 0。
- 房间/HUD 回归：全屏 29 项、数字 216 项、手牌数量/副露组合 168 项通过；最大手牌中心偏差 0.016px。
- 横竖屏回归：27 项行为检查与 26 项几何检查通过。统一提示与特殊牌双击回归、触屏双击不缩放回归通过。
- 单元测试：按文件串行运行 229 项全部通过；并发运行曾因同时启动多个浏览器导致已有的 50ms 耗时断言超限，串行复测通过，未修改该断言。
- `node --check app.js`、项目 TypeScript 类型检查、`git diff --check` 通过。

报告与截图位于忽略入库的 `output/ui-seated-view.json`、`output/ui-layout-acceptance.json` 和 `output/seated-view-*.png`。

## 手测与边界

1. 手机竖屏创建房间，开局后横置；确认等待页仍竖屏，对局只有一套横屏布局。
2. 检查桌沿有轻微收窄、木边厚度，自己的牌为平直排布。切换 16:9 与 20:9，牌面不能被拉伸。
3. 从手牌左、中、右分别单击选中、再次点击普通牌出牌；特殊牌在 300ms 内双击开杠。操作后提示面板与手牌中心不得横移。
4. 牌数减少并出现碰杠副露时，检查剩余手牌仍居中；点击提示先高亮、再次点击确认。
5. 牌河满牌时检查四区都完整可见；最新弃牌应在原位置放大，下一家操作后原位缩回。
6. 检查方向、杠型、翻皮墩号、摸补文字为正向清晰文字；操作按钮可正常点击。

实体 iOS/Android 设备尚未逐机测试；本轮使用 Edge 触屏模拟。牌、按钮、玩家信息均须完整可见。
