# 开局发牌动画

每局由服务端完成发牌后，前端使用该局初始快照重放发牌表现，不改变规则、真实取牌顺序、手牌、副露、墙数或网络协议。

## 表现

- 现有开局骰子提示收起后开始；每家按三轮、每轮四张取牌，随后每家补一张至十三张，庄家最后补第十四张。
- 按庄家起座依次展示四家；每批间隔 145ms，单张飞行 360ms，同批四张相差 12ms，整段约 2.68 秒。
- 从桌上 136 个固定牌墙格位的墙头反向取 53 个展示起点，跳过翻皮格；临时牌背逐批离开桌面，到达各家真实手牌 DOM 的坐标。
- 自己的牌接近落点时亮面，三家对手只展示牌背。没有手或人物模型，也不增加素材与依赖。
- 所有落点一次读取，动画通过独立层的 transform/opacity 完成；真实手牌容器不重排，完成后去除临时层并显示最新快照。

## 生命周期与交互

- 仅完整、尚未出牌或杠牌的真实开局快照触发；测试夹具、中途重连、普通摸牌和杠后补牌不触发。
- 房间、局数、骰子及皮子组成去重键，当前页面与 sessionStorage 均记录；重复 HTTP/SSE、刷新同局不重播，下一局可正常播放。
- 动画期间禁止本地手牌单击/双击、Enter、提示与吃碰杠胡按钮输入。服务端继续运行，网络快照继续接收，只暂缓画面绘制；完成后绘制最新状态。
- 手机尚未横置时等待旋转引导结束；正在飞牌时改变舞台尺寸直接完成清理。切后台、返回房间、退出、断连或结束牌局都会清除临时节点和输入锁。
- 浏览器减少动态效果设置、不支持 Web Animations API 或动画异常时直接显示真实牌局，不留下空白手牌；另有完成超时清理。
- 沿用原有“对局中不能离房”的规则，动画不放开这个限制。

## 文件

- `src/ui/opening-deal.js`：纯展示批次/起点规划、去重、动画与清理控制器，文案集中在 `DEAL_TEXT`。
- `app.js`：串接骰子结束、开局渲染、快照暂缓、输入锁及方向变化；规则入口仍由现有服务端校验。
- `landscape.css`：临时动画层、牌背与手牌遮罩，沿用现有木桌与麻将牌样式。
- `tests/opening-deal.test.js`：轮庄、四张批次、尾张与翻皮起点、真实开局识别与状态守恒。
- `tests/ui-opening-deal.mjs`：真实 HTTP/SSE 房间、手机/PC 动画与隐私、输入保护、稳定落点、重复快照、刷新、换局、人机提前出牌、旋转/离房及减少动态效果回归。

浏览器截图和结果保存在忽略入库的 `output/opening-deal-*.png`、`output/opening-deal-verification.json`。

本轮验证：Edge 155 手机触屏模拟 844×390、PC 1280×720，另以 640×360 检查减少动态效果和动画失败恢复，8 组浏览器场景通过；原桌面验收 15 个满牌/副露场景、20 个手牌数量场景、20 个真实输入场景与统一提示/特殊杠回归通过。243 项单元测试、项目类型检查及新增模块的独立 JavaScript 类型检查通过。未逐机测试实体 iOS/Android。
