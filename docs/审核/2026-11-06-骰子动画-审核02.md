## 需求核对及修复

1. 保留原有两颗 DOM 骰子的颜色、材质、点位和 1.8 倍放大。以两组独立单次关键帧代替 200ms 循环摇摆，具有起势、翻滚、衰减、回弹和归正；两颗分别使用 940ms、延迟 35ms 后 965ms 的轨迹。
2. 换面按经过时间推进，两颗节奏不同；约 686ms、807ms 锁定真实结果，随后在约 902ms、961ms 进入稳定尾段，最终等效零旋转。不用动画计算或修改业务点数。
3. 审核发现实际等待没有仅由停留常量决定：发牌逐牌插入、移动四角探针，重复强制布局，定位时本机单次准备约 11.7 秒，阻塞画面更新。新增 `tilePlanes()` 合并整批探针的写入和读取，沿用原四角矩阵公式；取消或异常时清理全部临时节点。没有把计算移到摇动之前或其他等待阶段。
4. 审核发现繁忙换局时 rAF 时间戳与 CSS 起点错位：CSS 仅播放约 721ms 就被清理，存在突然落定。`app.js` 改用既有 CSS 动画的 `currentTime` 同步换面及结束判断；无查询能力时按 `performance.now()` 降级。真实换局复查中两颗动画达到各自尾段后才清理。
5. 保留原播放代次、已播/待播去重和单次结束守卫。取消时清理计时器及 rAF；展示结束仍通过原 `finishDiceIntro → openingDeal.play` 衔接，不增加握手、规则等待或动画结束事件监听。
