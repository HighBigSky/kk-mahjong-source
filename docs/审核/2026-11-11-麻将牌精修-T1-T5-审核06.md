### 验证脚本调整及原因

1. `ui-tile-glyphs.mjs`、`ui-tile-materials.mjs` 增加 `KK_TILE_BASELINE`，默认历史值不变，本次显式传入正式 Base。四个牌面入口增加 `KK_UI_OUTPUT`，避免覆盖以前审核输出。
2. 材质脚本保存相同场景 Base/current 原始截图；线上运行时先在自己创建的测试房间实际点击选牌及出牌，再冻结客户端展示夹具。夹具不发送游戏动作、不改生产规则。
3. `tile-material-checks.mjs` 的旧断言锁定 `.025W` 倒角。保留首次失败记录，将获准精修的预期更新为 `.022W`，并从长度检查加强为两个场景光方向分量检查；外框、圆角、面宽、投影和描边保护不放宽。
4. 旧脚本把牌墙摸/补槽的状态内环当作普通主影。正式 Base 的 `landscape.css:899` 起已有此带模糊的内环，且本次未修改该文件。现在只对实际标记牌精确验证内环的零偏移、`.055W` 模糊、`.025W` 扩展；普通牌仍按原影子比例检查，同时要求当前与 Base 的全部接触/标记内影完全一致。
5. `ui-tile-size.mjs` 的“所有牌与本家手牌等大”假设早于正式 Base 的独立手牌放大和公开区容量约束。同一固定 Base 已复现相同失败，见 `size-baseline/ui-tile-size.json`。检查现按既有分区 CSS 牌框验证反投影形状及 5:7 比例，保留原 `.07/.08px` 精度、136 槽、稳定尺寸、点击热区、边界、遮挡、重叠和满牌河格序检查。没有为了测试改变产品几何。
6. 尺寸脚本原先逐牌四次写入/读取零尺寸探针，完整四客户端矩阵较慢。将同样的临时探针批量写入、读取和移除，并对每个已有分区/座位抽样与原 `quad()` 方法比较，要求误差不超过 `.001px`；不更改生产测量器，也不调整原有通过阈值。未完成的旧运行已停止，没有计为通过，最终结果来自修改后的完整重跑。
