# KK麻将 · 设计规格

## 对局主界面

牌桌采用玩家落座后的第一人称透视：台呢、四边胡桃木桌框、牌墙、对手手牌、牌河及中央方向盘共用一个 CSS 透视投影，远端收窄、近端展开，左右牌墙朝远端汇聚。自己的直立手牌位于近端，头像、顶栏与操作按钮保留屏幕坐标，四家头像尺寸统一，文字清晰并保留安全点击区域。视觉延续深墨绿、烫金、象牙牌面与绿色树脂牌体。

最新打出的牌在自己刚落入牌河的实际位置原地适度放大，空位足够时最多约 **1.5 倍**，拥挤时按邻牌、牌墙和操作区的实际空隙限制放大上限。与原牌保持相同的朝向及桌面透视，不移到桌中央，也不显示额外姓名标签。直到下一次有效出牌、过或吃碰杠胡响应后原地缩回；实际取走的牌随吃碰杠胡撤去，不回到已经空出的牌位。原牌河中的实牌始终保留原位、朝向出牌者，放大层只作展示且不拦截选牌和操作。自动摸牌、重复快照、语音状态和断线重连不当作响应，已经收回的同一张牌在本标签页刷新后也不重播。缩回动画遵循系统减少动态效果设置，不改变牌局、计时或响应顺序。

四方牌河按各自出牌者的阅读方向摆放：本人下方为 0°、对家上方为 180°、左家为 90°、右家为 -90°，旋转包含牌面、倒角与树脂牌身。每家预留 **27 个固定格位**：上下为 9 列×3 行，左右为 3 列×9 行。按玩家自己的左手边起排，每行九张，满行后向桌心增加下一行；仅设置网格位置，实牌 DOM 与出牌索引仍按时间顺序保留，牌河完整显示、不截取记录。容量与桌内位置集中在 `src/ui/river-layout.js`。牌面保持 5:7 长宽比，采用双倍局部尺寸绘制矢量牌面，再等比投影至桌面；四家使用相同实物牌宽。牌区仍按暗手、牌墙、牌河由外至内排列，左右牌墙内收以均衡间距，牌桌尺寸、桌沿、材质与相机参数保持不变。

牌河、中央罗盘、牌墙、暗手和公开副露分别占用独立区域。普通副露、单张杠、摸补牌标记均保留显示空间。验收以每家 27 格满牌夹具检查布局，四家同时满河只是超出实牌总量的展示压力测试，不代表真实牌局能同时出现四家各 27 张。实际实牌仍由规则及快照决定，最小支持的对局画面为 640×360，直到 PC 1920×1080；所有牌完整位于桌内，无滚动条、裁剪、重叠或遮挡玩家信息和操作按钮。

容量计算：启用翻痞时，`136−1−4×13＝83`，庄家首次摸牌包含在这 83 次预算中；不翻痞时预算为 84。无吃碰杠的轮转下单家最多约 21 张，不能将此数作为含跳家的容量。`tests/river-capacity.test.js` 使用动态规划穷举放宽后的所有座位转移：状态为已消耗摸牌数、四家各 0～4 组领取副露数量、最近出牌者；普通摸打消耗一份预算并顺移一席；吃碰允许任意非出牌者领取、消耗领取者一组副露额度，原出牌者牌河减一、领取者打出一张。领取不限制牌型、忽略补牌消耗，是比真实玩法更宽松的模型。83 和 84 两种预算下，任意中途状态的单家留河数均不超过 **27 张**。该数是安全上界，并不宣称真实牌型必能达到。暗杠、补杠、单张杠及明杠补牌只会额外消耗牌墙，胡牌则提前结束，均不能突破此界；全桌留河也不超过 83 张（无翻痞 84 张）。

## 入口、等待与对局方向

创建／加入房间及等待好友、添加人机、准备阶段使用竖屏页面。方向策略只由房间状态与路由决定：房间状态为 `playing`、`dealing` 或 `ended`，且当前未返回房间面板时，对局使用一套 **最小宽高比为 16:9 的横屏舞台**；返回房间面板或离开房间时恢复竖屏。设备方向与屏幕宽高比只用于缩放和显示旋转提示，不决定入口或对局版式。刷新／重连按恢复后的房间状态与当前路由展示。

手机与 PC 共用横屏对局的位置、比例和样式，舞台统一使用可用宽度，高度取可用高度与宽度的 9/16 中较小者；横置手机铺满，窄 PC 窗口保留上下留边，安全区扣除刘海与底边。手机与 PC 在创建／加入房间的用户手势同步链请求根容器全屏，离开房间时退出；全屏与方向独立。手机通过粗指针输入能力识别，开始对局时尝试 Screen Orientation API 横屏锁定；锁定失败且仍竖拿时显示「请横屏使用」的 `#rotate-guide` 引导层，横置后显示完整牌桌。PC 精细指针设备不请求方向锁定，不旋转页面，在任意窗口比例下保持同一横屏布局。只保留手机与 PC 的适配范围，不维护其他设备版式、屏幕阈值分支或缩放系数。

顶栏保留金币、余牌、皮子癞子、连接状态与音效／设置；余牌紧挨金币。中央罗盘显示两颗骰子，较小点数带金边，翻到的墩位在牌墙上标「皮·N」。吃碰杠胡过、「下一局」与轮到自己时的「提示」使用牌桌右侧操作区；「胡」保留朱红强调。手牌位于下方，玩法说明与返回房间放在设置中。对局、设置、规则和结算使用同一舞台比例；等待房间面板使用竖屏结构。

实现使用 HTML / CSS / SVG，视觉层与规则引擎分离；牌桌、对手、牌河、操作、手牌、弹窗分别具有独立的 DOM 和样式。13 张暗牌排列后，普通摸入牌单独展示；副露展示在暗牌左侧，避免占用操作按钮。按钮保留独立禁用、hover、按下与键盘焦点状态，不新增运行依赖。

## 已确定的基础玩法

- **人数与轮庄**：4 人，下一局逆时针轮流坐庄。按当前界面座位为下方你 → 右方云舟 → 上方阿福 → 左方小棠；重新发牌保留当前局数和庄家。
- **发牌与首出**：庄家起手 14 张，三位闲家各 13 张，庄家先出牌。界面在当前庄家座位显示「庄」标记。
- **用牌**：共 136 张，无花牌。万、筒、条各 1–9，每种 4 张，共 108 张；东、南、西、北、中、发、白各 4 张，共 28 张，其中包含 4 张红中。
- **单张红中杠**：红中只作特殊杠牌（皮子），不能直接打出、吃碰或作普通杠。轮到自己出牌时，可自行选择用 1 张红中杠出，随后补摸 1 张，仍由自己操作；也可以保留到之后再选择。多张红中可逐张杠出。每张已杠红中单独记录，不计入普通面子的组数，普通副露区与胡牌展示据此区分。
- **操作反馈**：合法时显示「杠」按钮；若同时有普通杠或多种可选操作，弹出选择面板，红中选项明确提示「补摸 1 张」。各家座位显示红中杠记录数量。

胡牌方式按后文已确认的二五八将、开口癞子限制与四种大胡执行；抢牌优先级和金币结算沿用基础演示实现，计分尚未定稿。红中未增加百搭或专属番分规则。

## 导出与后续扩展

### 半立体视觉更新

根据后续要求，游戏由平面外观更新为半立体效果：

- **麻将牌**：保留原矢量牌面，使用分层 CSS 绘制象牙色正面、柔和倒角、绿色树脂牌体及右侧/底侧厚度。牌河、手牌、副露、弹窗按显示尺寸分别控制厚度；选中牌的阴影随抬升加深。
- **牌桌**：胡桃木桌沿与金色嵌线，底部浅桌裙表现厚度；绿色台呢具有细密织纹和内凹阴影，中央方向盘呈漆面嵌入效果。
- **照明**：统一左上亮、右下暗，接触阴影突出牌落在台面的关系。保持牌面清晰、按钮与文字安全边距。
- **实现**：`table-depth.css` 和 `tiles-depth.css` 独立于规则和原布局。无需增加图片下载、3D 库或运行依赖。

### 传统四方座位更新

按用户最终要求采用传统麻将的上、下、左、右四方布局。当前安排：上方阿福（西）、下方你（东）、左侧小棠（北）、右侧云舟（南）。对家的头像相对，风位与中央方向盘和各自牌河一致。

四家统一使用头像、昵称、金币和状态三行信息的座位徽章。玩家本人的头像从页头移至下方座位，顶部保留金币总览与音效/设置；轮到任何一家时，其座位高亮。木质牌桌居中，左右信息栏位于牌桌外侧，各家副露独立展示，不遮挡摸打和吃碰杠胡操作。

座位共用样式位于 `seats-layout.css`，横屏对局位置由 `landscape.css` 统一定义。SVG 可按图层／元素编辑和导出，牌面 symbol 使用 `tile-0` 到 `tile-33`；对局预览按 16:9 舞台输出。

### 翻皮子定癞子（固定玩法）

翻皮子定癞子为固定规则，每局发牌前都会生效，设置中没有开关。顶部金币与设置按钮之间显示本局皮子和癞子，各用一张半立体牌及文字标注；手牌中的红中、皮子、癞子分别带小型「红」「皮」「癞」角标（只标牌种，与副露区杠出实牌的标记同义），保持牌面主体与原出牌热区。该显示层使用独立 `laizi.css`，不改变上下左右座位及吃碰杠胡过分区。

开局发牌前掷两颗骰子，取较小点数，从牌墙末端数到对应墩，每墩 2 张，翻上面一张实物牌作皮子，留在原位明示。同花色取下一张为癞子，9 回到 1。字牌按东、南、西、北、中、发、白七种统一循环。若直接翻到红中，或算出的癞子为红中，则把一张实际白板换到选定位置作皮子、发财作癞子；原翻出的红中或北风回到白板原位置。四张红中继续作为可单张自主杠出的特殊牌；普通翻到白板仍以东风为癞子。

普通发牌、摸牌从墙头取；红中杠、明杠、暗杠、补杠后的补牌全部从墙尾取，跳过已翻皮子。桌上沿四边完整展示牌墙的 68 个固定墩位，每边 17 墩，每墩上下两张；墙尾从下边左端开始，沿下 → 右 → 上 → 左连续排布。已经取走的实牌留下空槽，每张剩余牌对应一个牌背，牌背数与服务端及中央余牌数同步；翻出的皮子单独拥有、不计余牌。墙头用青色「摸」标记、墙尾用金色「补」标记，最后一张可同时标记，牌空时两标记均消失。双骰和翻皮墩数显示在罗盘下方，皮子始终在骰子选定的原墩上层。`wall-layout.css` 与 `src/network/wall-view.js` 独立承载展示，只有公开皮子显示牌面，其余始终为牌背，不公开牌墙内容。顶部明示区仅是同一皮子的展示。牌墙与牌河、暗手、副露分别留出安全边距。

启用时起手暗牌共 53 张、明示皮子 1 张、牌墙 82 张，总数仍为 136，每种 4 张。癞子允许替代缺牌，吃碰杠按实际牌面；癞子作将、开口数量限制与大胡豁免按后文执行，正式结算仍待制定。

红中胡牌限制：暗手中有红中时，不显示胡牌按钮；有合法操作时，操作区提示「先杠出红中，才能胡牌」。红中手牌带「红」角标，点击只提示规则，鼠标、触摸与键盘均不能将它打出。出牌提示在可补牌时聚焦「杠」按钮，保留玩家确认与自主选择时机；无余牌时只推荐其他可出牌。全部红中逐张杠出后，再判断能否胡牌。

### 操作按钮按条件显示

吃、碰、杠、胡、过只在服务端确认当前合法时显示，其他按钮隐藏且禁用；没有可执行操作时隐藏整组操作区。可用按钮居中排列，保留统一尺寸与原有点击区域，隐藏不改变手牌位置。网络请求中、断线暂停及结算后同样隐藏不可用操作；「过」仅在可以响应他人出牌时显示。

### 癞子杠

本局癞子可以像皮子一样单张杠出：从墙尾补摸一张，不占普通面子，按2倍底分结算。手牌同时有皮子和癞子时可分别声明对应杠型（唯一的杠选项直接执行，不弹选择框），癞子留在手里继续当百搭。杠出的实牌与皮子杠共用 `piziGangs` 记录，界面按牌面区分——与皮子同面标「皮」，与本局癞子同面标「癞」；座位角标分别累计「皮×N」「癞×N」。人机不会主动杠癞子，保留百搭用于成牌。

### 公开副露与皮子单张杠

开启翻皮子时，手中与实际皮子同牌面的牌完全沿用红中限制：可在自己出牌回合自主单张杠，从墙尾补一张，不占普通面子，按1倍底分结算；禁止直接打出、吃碰、普通杠，以及携带未声明皮子胡牌。墙上已翻出的皮子留在原墩，只用于确定本局规则，不可用于杠；其余三份实牌可以从暗手声明。`piziGangs` 与 `redGangs` 独立拥有实牌并一同纳入 136 张守恒，未开启时 `piziGangs` 为空。

## 二五八将、开口与大胡

屁胡为四组顺子或刻子加一对将，天然将须同花色同点数的二、五、八；一张二五八配癞子、两张癞子均可作将。吃、碰、明杠触发开口，补杠继承此前的碰；暗杠及红中、皮子单张杠不触发开口。屁胡未开口可用多个癞子，但只能自摸，不能接胡；开口后最多一个癞子，可以自摸或接胡。七对、碰碰胡、将一色、风一色这四种大胡未开口也可接胡。

四种大胡为七对、碰碰胡、将一色、风一色，均豁免二五八将及开口癞子数量限制。七对无普通副露，四同牌可计两对；碰碰胡由四组刻子或杠加一对组成，不含吃牌。将一色要求暗手和普通副露均为二五八；风一色要求均为全部七种字牌。将一色、风一色不要求组合结构，但仍须满足当次胡牌的有效张数，不能以未摸牌的十三张直接自摸胡。暗手癞子可替代所需牌；公开副露按实际牌面。红中、皮子必须先杠出的规则继续优先适用。

新增牌型不自行增加番分。结算沿用原天然胡牌形状的演示计分，等待后续确定正式结算规则。

所有人的吃、碰、明杠、暗杠、补杠，以及单张红中／皮子杠均在各家手牌旁公开实际牌面，单张牌标「红」或「皮」，普通副露按组标明动作。对手副露和暗手合在 `opponent-rack` 中连续排列；本人副露紧贴暗手左上方，保留完整手牌尺寸和点击热区。所有观察者按自己的上下左右座位映射看到相同公开牌，对局进行时其他人的未声明暗手仅显示牌背。牌数徽章是辅助，不能替代实际牌面展示。

胡牌结算时四家剩余手牌全部亮出，包括真人与人机；三家对手的原牌背原位替换为已有 SVG 牌面，保持尺寸、排列与副露位置。关闭结算弹窗后仍可查看，刷新或重连后的结算快照同样亮牌。只有 `ended` 且结果为 `win` 时公开；流局保持原有隐藏，开始下一局立即恢复暗手隔离。牌墙、身份令牌与随机信息继续留在服务端。小尺寸亮牌保留癞子金边和无障碍名称，隐藏会遮挡图案的角标。

吃、碰、杠、胡完成后，在操作者真实暗手牌堆的正前方显示单字彩色提示。上家在手牌下方、下家在手牌上方、左家在手牌右方、右家在手牌左方，全部朝向桌心。提示中心跟随实际手牌牌张的联合边界，不跟随包括副露在内的整条牌架；吃碰杠使暗手变短或窗口缩放时重新对齐。下家提示在手牌标题和公开副露的上方，避免盖住牌与文字。优先使用 6cqw 见方、约 5.6cqw 的字，沿同一中心轴避让牌墙、牌河、牌河计数、罗盘与操作区；拥挤时缩小，不漂移到牌桌角落。不占布局空间、不接收点击、不添加持续动画。吃用青绿 `#9fd9b3`、碰用浅蓝 `#9bcce7`、杠用金色 `#f1cf83`、胡用朱红 `#ff9385`。普通杠与红中、皮子单张杠统一显示「杠」。服务端根据实际公开副露和结算变化发布动作，避免把等待中或败选申请显示为已执行；真人与人机共用通知。吃碰杠 2400ms 后隐藏，同一通知重复接收不会延长显示；胡保留到下一局，后续有效动作替换之前的提示。换房、重开或下一局清空。

## 房间全屏与 HUD 对齐

全屏由 src/ui/fullscreen.js 跟随房间成员状态维护；方向由 orientation.js 跟随对局状态和房间路由维护。失败时保留 100dvh 视口与安全区布局，显示可添加到主屏幕的提示，不阻止建房和出牌。刷新会自动尝试恢复，若浏览器因缺少用户手势拒绝，则在下一次普通房间操作中重试。

HUD 房间码与余牌数字共用等宽字体栈、tabular-nums、字号、字重、颜色和基线，分别占六位和三位，余牌以零补位。房间页房间码复用数字样式。暗手容器始终对齐牌桌中心，副露独立位于左侧并在左右对称预留空间；1–14 张牌均不换行，牌少不放大，牌多按可用宽度收窄。
