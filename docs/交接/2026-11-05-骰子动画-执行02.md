## 实际调用关系

1. 房间网络状态更新触发 `roomChanged()`，由 `render()` 绘制中央骰子并调用 `renderDiceIntro()`。
2. 点数由现有游戏引擎 `newRound()` 内独立的 `_diceRandom` 生成，经快照进入 `game.wallInfo.dice`。`diceHTML()` 使用 `DIE_PIPS` 将点数映射到 3×3 骰面格，本次不修改生成或映射逻辑。
3. `renderDiceIntro()` 沿用房间、局数及点数构成的去重键，符合条件时调用 `startDiceIntro()`。减少动态效果时仍直接展示结果；普通模式将点数副本交给 `rollIntroDice()`，动画值不写回游戏。
4. `rollIntroDice()` 启动单次 CSS 运动和 `requestAnimationFrame` 换面时钟。换面进度由时间戳计算，不累计帧数；经过的时间越长，换面间隔越长。
5. 两颗骰子分别在约 686ms 和 807ms 锁定真实点数，之后继续小幅回弹和归正；约 902ms 和 961ms 已到达最终静止姿态。完整摇动在 1000ms 结束，随后保留原有 120ms 中央停稳阶段。
6. `showDiceIntro()` 继续一次性读取现有中央骰子和展示行的锚点，通过同一展示行的 transform 完成原有 1.8 倍放大；保持 800ms 后调用 `finishDiceIntro()`。
7. `finishDiceIntro()` 仍先通过 `dismissDiceIntro()` 结束当前状态，再调用 `openingDeal.play()`；没有等待中的发牌动画时按原逻辑 `render()`，随后刷新交互状态。重复结束调用由活动状态守卫阻止。

## 运动与落定

原实现每 200ms 循环一次，两颗骰子主要靠负延迟错开，点数固定每 80ms 改变，1000ms 时直接替换为最终骰面。

现在第一颗用 940ms 完成运动；第二颗晚 35ms 起势，用 965ms 完成运动，总摇动仍为 1000ms。两组关键帧采用不同的起落节点和旋转方向，主要翻滚后逐渐减小位移、倾斜、缩放及旋转增量。transform 的组合顺序固定为位移、平面旋转、Y 倾斜、X 倾斜、缩放，旋转中心固定。

真实点数在末次回弹开始时已经显示，最后关键帧停在原位置、原比例和正负 720° 的等效零旋转。中央骰面随后清理为普通结构时，所见点数和姿态已经一致，不靠结束瞬间换节点掩盖不同结果。
