## 调用关系与请求参数

1. `#room-bot-entry → roomOperation → prepareBotRoom()`：未入房时沿用 `nickname()`、`network.create(name,true)`；已有房仅补缺少的人机，已有机器人不重复添加；准备完成不自动开局。完整就绪时直接返回，无多余请求。
2. `#room-members .room-bot-add → roomOperation → prepareBotRoom({seat})`：仅添加当前指定空位，不要求混合房间符合快捷入口资格；只有补齐一真人三人机时才沿用既有真人 ready 行为。然后从权威状态收敛至相同选择界面。
3. `#room-start → roomOperation → startRoom(false) → network.start(null)`。
4. `#room-four-wilds → roomOperation → startRoom(true) → network.start(room.seat)`。客户端自身在 seats 数组中为相对 0；请求用 room.seat 实际座位，不使用相对 0 代替。
5. 原 `src/network/client.js` 序列保护、状态接收、addBot 相对到绝对座位转换、ready、refresh、leave 均原样保留。普通开始不关闭 room.laizi，不使用新的 mode 或 isBotRoom 参数。
6. 原服务端 `start()`、`_canStart()`、`canChooseFourWilds()` 继续最终校验权限、对局、人员和参数并启动；`snapshot()` 继续即时生成 fourWildsReady；`next()` 沿用锁定模式；`dealing`、`openingComplete()` 及人机调度保持原样。
