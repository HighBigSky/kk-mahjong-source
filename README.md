# KK麻将

一个无需第三方依赖的麻将浏览器游戏：创建、加入房间页面保持竖屏，进入房间后自动切换为横屏，离开房间恢复竖屏。创建好友房间获得 6 位房间码，邀请好友或由房主向空座位添加人机，凑齐四家轮流坐庄。支持 1–4 位真人搭配 0–3 位人机；各位真人都在自己的屏幕下方操作自己的手牌。房间内支持 WebRTC 实时开黑语音，严格 NAT 环境可配置 TURN 中继。

手机浏览器支持时自动尝试全屏与横屏方向锁定。不支持锁定（例如部分 iPhone 浏览器）时，房间与对局界面自动旋转为横屏布局；竖拿手机不会退回竖屏对局。房间弹窗、设置、规则和结算均随横屏适配，刷新恢复原房间后仍保持横屏。

## 启动

安装 Node.js 18 或更新版本后，在本目录打开终端：

```sh
npm start
```

电脑访问 **http://localhost:5173**。同一局域网手机访问 `http://电脑的局域网IP:5173`。如系统提示防火墙权限，可仅允许自己的专用网络。请通过服务器访问，直接双击 HTML 不能加载 ES 模块。无须运行 `npm install`。

也可以双击 `启动游戏.cmd`。

## 邀请好友

1. 输入昵称，点击「创建好友房间」。翻皮子定癞子固定开启，无需也不能在房内切换。
2. 点击「复制邀请」，把网址和 6 位房间码发送给好友。好友打开同一网站、输入昵称及房间码加入；邀请网址会预填房间码。
3. 开局前房主可向空位添加或移除人机，也可保留空位继续邀请真人。座位已满时，先移除人机再让好友加入；对局中不能增删人机或替换真人。好友离线且无法重连时，房主可点击「移除离线」清出该座位；房主自己离线时，其他真人也可移除此座位。
4. 四个座位到齐、真人分别点击「准备」后，由房主开始对局；人机自动准备，并由服务器按现有策略操作。
5. 结束后由房主开始下一局，沿用本房间积分和轮庄；即使结算后有人离开，剩余玩家的积分与局数仍会保留。

**异地异网需要部署公网服务器。** 本项目已提供 Node.js 房间服务和 Docker 配置，但尚未部署公网地址。`localhost` 和局域网 IP 不能直接发给异地好友使用；房间码也不能替代网站地址。部署后大家访问同一个公网 HTTPS 网址即可，不需要同一 Wi-Fi 或 NAT 打洞。详见 [联机部署](docs/联机部署.md)。

## 操作

- 点选手牌，再点一次打出；桌面可用方向键选择、Enter 出牌。
- 手牌优先将红中和皮子杠牌放在最左侧，癞子排在第二组，其余牌从左到右由小到大排列。普通摸入牌单独放在最右侧；摸入红中、皮子或癞子时直接归入对应优先组。
- 吃 / 碰 / 杠 / 胡 / 过仅在当前满足条件时显示，不可用的操作自动隐藏。
- 吃、碰、杠、胡实际生效后，操作者牌桌前显示对应彩字，全桌同步可见：吃为青绿、碰为浅蓝、杠为金色、胡为朱红。吃碰杠约显示 2.4 秒，胡保留到下一局；红中杠、皮子杠、明杠、暗杠、补杠统一显示「杠」。等待中的申请、被更高优先级压掉的申请及非法操作不显示。
- 多组吃牌或多种杠牌时弹出组合选择。
- 红中及与本局皮子同牌面的手牌只作特殊杠牌，不能直接打出。轮到自己出牌时，可通过「杠」选择单张红中杠或皮子杠；手中没有皮子时，本局癞子也可以当皮子单张杠出，两者都在手时只提供皮子杠。每杠一张从墙尾补摸一张，也可以暂时保留。手牌角标只标牌种：红中标「红」、皮子标「皮」、癞子标「癞」，与副露区杠出实牌的标记一致；「只能单张杠出」写在悬停提示和顶部提示里，出牌提示优先提示单张杠。
- 每家已杠出的红中和皮子均按实牌逐张摆在手牌旁，分别标「红」「皮」；吃、碰、明杠、暗杠、补杠按组展示。所有玩家都能看到这些公开牌，对局中其他人的暗手继续隐藏。本人副露紧贴手牌左上方，上下左右对手的副露与暗牌共用一排或一列。
- 有人胡牌后，四家的剩余手牌全部亮出，所有真人和人机的牌面均可查看；关闭结算弹窗后仍保持亮牌，刷新或重连也能查看。下一局重新隐藏其他三家的暗手；流局沿用原有展示。
- 翻皮子定癞子为固定规则，每局发牌前都会翻皮定癞，设置中没有开关；顶部常驻展示本局皮子和癞子，手牌中的皮子与癞子分别带「皮」「癞」角标。
- 开音效后，任何一家打出牌都会同步读出牌名（如「一万」「九筒」「红中」「发财」「白板」），用浏览器自带语音合成，不额外引入依赖；连续出牌时只读最新一张，不排队。
- 「出牌提示」并入牌桌右侧的操作列，只在轮到自己、且没有吃碰杠胡可选时出现，提示后仍须自己点牌确认。
- 点击任意牌河查看全部出牌；牌桌只显示最近的出牌，保持布局整齐。
- 右上角设置集中放对局外的操作：音效开关、玩法说明、返回桌面（回到房间面板）。设置里不再有牌名开关，手牌只显示牌面本身；打开个人弹窗不会暂停其他玩家。有人掉线时整桌暂停，重连后继续，不由电脑代打。
- 人机每次操作间隔约 650 毫秒，使用原有决策策略；真人的出牌与吃碰杠胡仍须自己选择。添加人机不改变麻将规则或计分。
- 顶部麦克风按钮打开「开黑语音」面板，手动开启后申请麦克风；支持静音、退出语音和座位说话高亮。语音通过 WebRTC 在真人之间直连，服务器只转发 SDP/ICE 信令；严格 NAT 环境需配置 TURN 中继。浏览器要求 HTTPS 或 localhost 才能使用麦克风，进入房间后刷新需重新开启语音。
- 昵称和个人设置保存在当前浏览器；房间与积分保存在服务器内存。原标签页刷新可恢复座位，服务器重启后需重新建房。

## 规则范围

已确定的基础配置：

- **4 家对局**，可由 1–4 位真人与 0–3 位人机组成；下一局按逆时针轮庄：下方 → 右方 → 上方 → 左方 → 下方。房主开始下一局时保留房间积分并更新局数与庄家。
- **庄家 14 张、闲家各 13 张**，由庄家先出牌。
- **共 136 张，无花牌**：万、筒、条各 1–9，每种 4 张，共 108 张；东、南、西、北、中、发、白各 4 张，共 28 张。
- **4 张红中为特殊杠牌（皮子）**：不能直接打出，不能吃碰或作普通明杠、暗杠、补杠。轮到自己出牌时，手中任意 **1 张红中即可单独杠出**，时机由玩家选择；每次将 1 张红中移至独立的红中杠记录，再补摸 1 张，仍由该玩家操作。多张红中可逐张选择杠出，也可以保留。红中杠不占普通面子的组数。
- **皮子杠完全沿用红中规则**：手中与实际皮子同牌面的牌可逐张自主杠出，从墙尾补牌，不占普通面子、不单独计分；不能打出、吃、碰或作普通杠。牌墙中翻开的皮子仍留在原位，另外三份可以从手牌杠出，使用独立 `piziGangs` 实牌记录，全部公开可见。
- **癞子也能当皮子杠**：手中没有皮子时，本局癞子可以单张杠出，同样从墙尾补摸、不占面子、不计分；手牌同时有皮子和癞子时只提供皮子杠，癞子继续留在手里当百搭。杠出的实牌同样记入 `piziGangs`，牌桌按牌面区分——与皮子同面记「皮」，与本局癞子同面记「癞」，亮在副露区公开可查。
- **持红中或皮子禁止胡牌**：暗手中有红中或本局皮子时，不能自摸或点炮胡牌；须先将全部暗手特殊牌逐张杠出，再按当前手牌结构判断胡牌。已杠记录不影响胡牌。
- 特殊杠须有余牌可补摸。若牌墙已空且自己的暗手只剩红中或皮子，无法杠、出牌或胡牌，本局按流局结束。
- **额外癞子为本项目固定玩法（每局都翻皮定癞）**：开局掷两颗骰子，取较小点数，从牌墙末端数到对应墩（每墩 2 张），翻上面一张实物牌作为皮子，留在该位置明示。万、筒、条取同花色下一张作为癞子，9 循环到 1。字牌按东 → 南 → 西 → 北 → 中 → 发 → 白 → 东统一循环。
- **红中例外**：若直接翻到红中作皮子，或按下一张规则算出红中为癞子，均将一张实际白板换到骰子选中的位置作皮子、发财作癞子。原翻出的红中或北风回到白板原来的位置，保证 136 张牌及每种 4 张守恒；四张红中继续按单张杠规则处理。普通翻到白板仍按循环规则以东风作癞子。
- 皮子在发牌前翻出，不进入手牌、出牌或副露。每局都启用癞子：庄家仍为 14 张、闲家各 13 张，起手余牌为 82 张。
- **摸牌方向与剩余牌堆**：普通摸牌与起手发牌从墙头取；红中杠、皮子杠、明杠、暗杠、补杠后的补牌统一从墙尾取，并跳过已翻皮子。桌上四边各有 17 个固定墩位，每墩上下两张；剩余实牌逐张显示牌背，已经取走的位置留空，牌背总数严格等于顶栏「余牌」胶囊里的实时张数。青色「摸」标记指向墙头的下一张普通摸牌，金色「补」标记指向墙尾的下一张补牌；两颗骰子摆在牌桌正中央，取较小点数的那颗带金边，翻到的墩位在牌墙上标「皮·N」。牌河四边同尺寸、同为两行：上方与下方各 6 列 12 张，左右各 3 列 6 张，围绕中央罗盘对称。皮子不计入余牌数，顶部皮子是同一实牌的展示，不额外计入牌数。

胡牌规则已确定如下，支持自摸和点炮：

- **屁胡**：四组顺子或刻子，加一对同花色、同点数的二、五、八作将。一张二五八实牌配一张癞子、两张癞子均可作将；其他实牌不能配一张癞子作将。
- **开口与癞子**：吃、碰、明杠算开口，补杠延续之前的碰；暗杠、红中单张杠、皮子单张杠不算开口。屁胡未开口可使用多个癞子，但只能自摸，不能接胡；开口后最多一个癞子，可以自摸或接胡。以胡牌暗手中参与判定的癞子计算；已经声明的普通副露使用实际牌面。
- **大胡**：七对、碰碰胡、将一色、风一色，均豁免二五八将和开口后的癞子数量上限，未开口也可接胡。七对仍须七组对子且无普通副露，四张同牌可计两对；碰碰胡须四组刻子或杠加一对，不能含吃牌。
- **将一色、风一色**：将一色的暗手与普通副露全部为二五八；风一色全部为东、南、西、北、中、发、白。两者只检查牌的范围，不要求四组加一对或七对的组合结构，胡牌张数仍须正确；癞子可替代该类牌，公开副露仍按真实牌面判断。红中及本局皮子在暗手中仍禁止胡牌。

吃上家、碰、明杠、暗杠、补杠与墙尾补牌继续沿用；吃碰杠使用真实牌面组合。抢牌优先级为胡 > 碰 / 杠 > 吃；同优先级取出牌者之后最近的一家。

当前采用**演示计分，尚未定稿**：基础 10；七对、碰碰胡、自摸各加 10，清一色加 20，字一色加 30。自摸其余三家各付一份，点炮一家付三份。杠暂不额外计分，也未增加红中专属番分。金币仅是本房间对局积分，没有充值或支付功能。

本次新增的大胡判定用于决定能否胡牌，未自行制定将一色、风一色的新番分；已有演示加分仍按原来的天然成牌条件计算，清一色加分不代表它获得本次大胡豁免。

不包含国标番数、抢杠胡、一炮多响、牌墙预留、四川血战或日式立直规则。不含账号、旁观或持久化排行榜。

- `docs/设计规格.md`：UI 分层与用户提供的素材提示词。
- `docs/联机部署.md`：公网、HTTPS、环境变量、Docker 与单实例运行约定。
- `deploy/`：阿里云部署脚本与说明——`install.sh` 一键安装、`update.ps1` / `更新到服务器.cmd` 一键更新、`Caddyfile.example` 域名反代示例、`turnserver.conf.example` coturn 语音中继配置、`部署到阿里云轻量.md` 全流程文档。

- `output/game-preview-1080x1920.png`：1080×1920 界面预览（完成视觉验证后导出）。

## 验证

```sh
npm test
```

规则测试涵盖胡牌分解、七对、牌数守恒、摸打、吃碰杠、单张红中杠、皮子单张杠、轮庄、翻皮子与癞子、抢牌优先级、玩家响应等待、随机种子复现、完整对局及积分延续。`npm test` 也包含好友房接口测试和语音测试，覆盖 STUN/TURN 配置、语音在线状态、SDP/ICE 信令定向转发、非法信令拒绝以及断线后语音状态清理；可用 `npm run test:online` 单独运行好友房接口测试。

`npm run test:ui` 执行四人独立浏览器的好友房用例，会自行启动测试服务器，覆盖创建、加入、准备、状态同步和刷新恢复；开发机需要已有 Playwright 与浏览器，运行游戏无需这些工具。旧的 `tests/ui-smoke.mjs`、`tests/ui-laizi.mjs`、`tests/ui-hand-visibility.mjs` 使用原单机状态夹具，尚未迁移，不能作为当前好友房界面的验收依据。

`node tests/ui-bots.mjs` 验证房主添加与移除人机、真人与人机混合开局及服务器自动操作；使用相同的本地浏览器测试环境。

`npm run test:ui:wall` 验证四种屏幕尺寸下的完整牌墙、逐张余牌同步、原位皮子、头尾摸补位置和联机同步；使用相同的本地浏览器测试环境。

`npm run test:ui:melds` 验证四人浏览器中的公开牌：真实点击红中杠、皮子杠、吃、碰、明杠、暗杠、补杠，逐一比对四个相对座位的牌面。另用 136 张守恒的显示夹具，覆盖四种尺寸下最多公开副露、四张红中加三张皮子杠且仍有完整 14 张暗手的布局，以及选牌和重复快照不重建牌面。夹具用于覆盖边界，不代表自然发出的完整对局。

`npm run test:ui:rules` 用四个真实浏览器验证普通胡的二五八将、开口癞子上限、未开口屁胡仅限自摸及四种大胡豁免。合法牌实际点击胡牌，四端同步结算并显示胡牌类型；非法牌的胡牌按钮隐藏，伪造请求由服务器拒绝且状态不变。测试夹具逐张分配真实 136 张牌。

`npm run test:ui:reveal` 验证自摸与接胡后四家原位亮牌、各观察者牌面一致、结算刷新重连、下一局恢复隐藏及流局保持原展示，并覆盖四种屏幕尺寸。`test:ui:bots` 另验证实际人机整局结束后的亮牌。

`npm run test:ui:notices` 用四个浏览器实际执行吃、碰、五种杠与胡，验证四家对应座位彩字、抢牌优先级、自动消失、重复快照不重播、胡字跨刷新保留与下一局清空，并检查四种屏幕尺寸下不遮挡牌面或操作区。

`npm test` 也会运行领域迁移安全网；可单独执行 `node tests/domain-invariants.mjs`，复现 200 局普通／癞子随机合法动作与 8 局 AI 对局，另有单独记录的真实发牌闭口屁胡自摸场景，逐步检查实牌守恒，并比较日志、计分与牌局状态。冻结的旧引擎 `tests/fixtures/engine-before-domain.js` 保持原样并受 SHA256 保护；测试用 `tests/legacy-wall-oracle.mjs` 仅在内存中显式适配已确认的骰子翻皮、红中例外、墙尾补牌、皮子单张杠、二五八将、开口癞子限制、闭口屁胡仅限自摸与四种大胡，使用冻结的分解搜索与计分作为对照；不宣称本次修改后仍与未适配新规则的旧对局一致，浏览器游戏不加载测试代码。

## 视觉设计

基准画布为 1080×1920，浏览器按 9:16 等比例适配，电脑居中显示。顶部金币 / 设置 → 四方玩家与居中牌桌 → 对局状态 → 统一吃碰杠胡过 → 手牌 → 辅助操作，区域独立。横屏对局把这条竖排结构重新排布：顶栏只留金币、余牌、皮子癞子、连接状态与音效/设置（余牌紧挨金币右侧）；正方形牌桌取舞台高度的 **75%**（早先 70%），桌上的牌河、牌墙、三家暗手与副露再放大 13–25%——牌河 5.2×7.28、暗手背 2.8×3.9、牌墙 2.85×3.99、自己副露 4.3×6.0 个桌子单位，中央罗盘缩到 16 单位、正中间摆两颗骰子（取较小点数的那颗带金边）；吃碰杠胡过（含回合结束的「下一局」、轮到自己时的「提示」）改成牌桌右侧的一列大按钮，避开右家座位卡并垂直居中；手牌行贴到屏幕最底部。四边牌河同尺寸、同为两行——上下各 6 列、左右各 3 列，围绕中央骰子对称，计数文字朝外。原底部栏已取消，玩法说明与返回桌面移入右上角设置。采用传统上下左右座位，各人自己的座位都显示在屏幕下方，其他三家按相对位置显示好友昵称。四家显示头像、昵称、金币、风位和当前状态；庄家标记随轮庄更新，副露分别靠近各家。闲家 13 张起手牌横向排列，红中杠牌优先置左、癞子第二；庄家多发的第 14 张及后续摸入牌若为普通牌则单独留间隔，红中或癞子归入对应优先组。吃碰普通杠后按规则减少暗牌，副露单独展示，红中与皮子杠另行记录并公开展示。

牌桌与麻将牌采用半立体材质：牌面有圆角倒边，绿色牌体在下侧和右侧露出厚度；选牌时增强悬空阴影。中央牌桌使用木质桌沿、金色嵌线、细织纹台呢和凹入式中控面板，光线统一从左上方照入。厚度绘制在原牌尺寸内，牌面保持正视，便于小屏识别与触摸。

头像和牌面均为手工绘制的原生 SVG，不是 AI 位图生成结果。无远程字体、素材、CDN 或安装依赖。素材随服务器提供；所有真人玩家需要持续连接同一房间服务器。
