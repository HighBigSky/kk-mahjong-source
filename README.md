# KK麻将

一个无需第三方依赖的麻将浏览器游戏：创建、加入房间和房间等待页面使用竖屏布局；开始发牌后进入统一的横屏对局布局，返回房间面板后恢复竖屏。创建好友房间获得 6 位房间码，邀请好友或由房主向空座位添加人机，凑齐四家轮流坐庄。支持 1–4 位真人搭配 0–3 位人机；各位真人都在自己的屏幕下方操作自己的手牌。房间内支持 WebRTC 实时开黑语音，严格 NAT 环境可配置 TURN 中继。

布局由房间状态和当前路由决定：`playing`、`dealing`、`ended` 且未返回房间面板时使用统一横屏舞台，横置时填满可用区域；窄窗口保持至少 16:9 并居中；其他状态使用竖屏入口与等待页。创建／加入房间的点击同步链先请求根容器全屏，手机与 PC 均适用，离开房间后退出；全屏不改变竖屏等待页。手机在开局时另尝试 Screen Orientation API 横屏锁定，仍竖拿时显示「请横屏使用」引导层。PC 不请求方向锁定、不旋转页面。不支持全屏或请求被拒绝时使用 100dvh 视口布局并提示添加到主屏幕；刷新恢复房间会自动尝试，若浏览器要求新的用户手势，则在下一次普通房间操作中重试。

## 启动

安装 Node.js 18 或更新版本后，在本目录打开终端：

```sh
npm start
```

电脑访问 **http://localhost:5173**。同一局域网手机访问 `http://电脑的局域网IP:5173`。如系统提示防火墙权限，可仅允许自己的专用网络。请通过服务器访问，直接双击 HTML 不能加载 ES 模块。无须运行 `npm install`。

也可以双击 `启动游戏.cmd`。

## 邀请好友

1. 输入昵称，点击「创建好友房间」。翻痞子定癞子固定开启，无需也不能在房内切换。
2. 点击「复制邀请」，把网址和 6 位房间码发送给好友。好友打开同一网站、输入昵称及房间码加入；邀请网址会预填房间码。
3. 开局前房主可向空位添加或移除人机，也可保留空位继续邀请真人。座位已满时，先移除人机再让好友加入；对局中不能增删人机或替换真人。好友离线且无法重连时，房主可点击「移除离线」清出该座位；房主自己离线时，其他真人也可移除此座位。
4. 四个座位到齐、真人分别点击「准备」后，由房主开始对局；人机自动准备，并由服务器按现有策略操作。
5. 结束后由房主开始下一局，沿用本房间积分和轮庄；即使结算后有人离开，剩余玩家的积分与局数仍会保留。

**异地异网需要部署公网服务器。** 本项目已提供 Node.js 房间服务和 Docker 配置，但尚未部署公网地址。`localhost` 和局域网 IP 不能直接发给异地好友使用；房间码也不能替代网站地址。部署后大家访问同一个公网 HTTPS 网址即可，不需要同一 Wi-Fi 或 NAT 打洞。详见 [联机部署](docs/联机部署.md)。

## 操作

- 点选手牌，再点一次打出；桌面可用方向键选择、Enter 出牌。
- 手牌优先将红中和痞子杠牌放在最左侧，癞子排在第二组，其余牌从左到右由小到大排列。普通摸入牌单独放在最右侧；摸入红中、痞子或癞子时直接归入对应优先组。
- 吃 / 碰 / 杠 / 胡 / 过仅在当前满足条件时显示，不可用的操作自动隐藏。
- 吃、碰、杠、胡实际生效后，操作者牌桌前显示对应彩字，全桌同步可见：吃为青绿、碰为浅蓝、杠为金色、胡为朱红。吃碰杠约显示 2.4 秒，胡保留到下一局；红中杠、痞子杠、明杠、暗杠、补杠统一显示「杠」。等待中的申请、被更高优先级压掉的申请及非法操作不显示。
- 多组吃牌或多种杠牌时弹出组合选择。
- 红中及与本局痞子同牌面的手牌只作特殊杠牌，不能直接打出。轮到自己出牌时，可通过「杠」选择单张红中杠或痞子杠；本局癞子也可以当痞子单张杠出，两者都在手时可分别选择对应杠型。每杠一张从墙尾补摸一张，也可以暂时保留。手牌角标只标牌种：红中标「红」、痞子标「痞」、癞子标「癞」，与副露区杠出实牌的标记一致；「只能单张杠出」写在悬停提示和顶部提示里，红中、痞子、癞子可在300ms内双击开杠。
- 每家已杠出的红中和痞子均按实牌逐张摆在手牌旁，分别标「红」「痞」；吃、碰、明杠、暗杠、补杠按组展示。所有玩家都能看到这些公开牌，对局中其他人的暗手继续隐藏。本人副露紧贴手牌左上方，上下左右对手的副露与暗牌共用一排或一列。
- 有人胡牌后，四家的剩余手牌全部亮出，所有真人和人机的牌面均可查看；关闭结算弹窗后仍保持亮牌，刷新或重连也能查看。下一局重新隐藏其他三家的暗手；流局沿用原有展示。
- 翻痞子定癞子为固定规则，每局发牌前都会翻痞定癞，设置中没有开关；顶部常驻展示本局痞子和癞子，手牌中的痞子与癞子分别带「痞」「癞」角标。
- 开音效后，任何一家打出牌都会同步读出牌名（如「一万」「九筒」「红中」「发财」「白板」），用浏览器自带语音合成，不额外引入依赖；连续出牌时只读最新一张，不排队。
- 「听胡」与「提示」合并为手牌右侧唯一提示入口：待打时显示“打 X → 听 Y（未见张数）”，已经听牌时在别人回合也显示；无听牌时隐藏。待胡牌面按种类数等比缩放，多牌时换行，极多时在浮窗内纵向查看，浮窗可随时关闭。第一次点击仅高亮建议牌，再次点提示或建议牌确认出牌，最多选择5条候选。
- 牌桌完整展示各家的当前牌河，点击任意牌河也可查看出牌历史。每家预留 36 个固定格位：上下 9 列×4 行、左右 4 列×9 行；四家围绕桌心等距对齐、共用桌面上的实物牌宽，牌区整体等比缩放，保留牌体建模、各家朝向与既有透视。牌列紧密摆放，增加出牌时不挤走已有牌。
- 右上角设置集中放对局外的操作：音效开关、玩法说明、返回桌面（回到房间面板）。设置里不再有牌名开关，手牌只显示牌面本身；打开个人弹窗不会暂停其他玩家。有人掉线时整桌暂停，重连后继续，不由电脑代打。
- 人机每次操作间隔约 650 毫秒，使用原有决策策略；真人的出牌与吃碰杠胡仍须自己选择。添加人机不改变麻将规则或计分。
- 顶部麦克风按钮打开「开黑语音」面板，手动开启后申请麦克风；支持静音、退出语音和座位说话高亮。语音通过 WebRTC 在真人之间直连，服务器只转发 SDP/ICE 信令；严格 NAT 环境需配置 TURN 中继。浏览器要求 HTTPS 或 localhost 才能使用麦克风，进入房间后刷新需重新开启语音。
- 昵称和个人设置保存在当前浏览器；房间与积分保存在服务器内存。原标签页刷新可恢复座位，服务器重启后需重新建房。

## 规则范围

已确定的基础配置：

- **4 家对局**，可由 1–4 位真人与 0–3 位人机组成；下一局按逆时针轮庄：下方 → 右方 → 上方 → 左方 → 下方。房主开始下一局时保留房间积分并更新局数与庄家。
- **庄家 14 张、闲家各 13 张**，由庄家先出牌。
- **共 136 张，无花牌**：万、筒、条各 1–9，每种 4 张，共 108 张；东、南、西、北、中、发、白各 4 张，共 28 张。
- **4 张红中为特殊杠牌（痞子）**：不能直接打出，不能吃碰或作普通明杠、暗杠、补杠。轮到自己出牌时，手中任意 **1 张红中即可单独杠出**，时机由玩家选择；每次将 1 张红中移至独立的红中杠记录，再补摸 1 张，仍由该玩家操作。多张红中可逐张选择杠出，也可以保留。红中杠不占普通面子的组数。
- **痞子杠完全沿用红中规则**：手中与实际痞子同牌面的牌可逐张自主杠出，从墙尾补牌，不占普通面子，按1倍底分即时结算；不能打出、吃、碰或作普通杠。牌墙中翻开的痞子仍留在原位，另外三份可以从手牌杠出，使用独立 `piziGangs` 实牌记录，全部公开可见。
- **癞子也能当痞子杠**：本局癞子可以单张杠出，同样从墙尾补摸、不占面子，按2倍底分结算；手牌同时有痞子和癞子时可分别声明对应杠型，癞子继续留在手里当百搭。杠出的实牌同样记入 `piziGangs`，牌桌按牌面区分——与痞子同面记「痞」，与本局癞子同面记「癞」，亮在副露区公开可查。
- **持红中或痞子禁止胡牌**：暗手中有红中或本局痞子时，不能自摸或点炮胡牌；须先将全部暗手特殊牌逐张杠出，再按当前手牌结构判断胡牌。已杠记录不影响胡牌。
- 特殊杠须有余牌可补摸。若牌墙已空且自己的暗手只剩红中或痞子，无法杠、出牌或胡牌，本局按流局结束。
- **额外癞子为本项目固定玩法（每局都翻痞定癞）**：开局掷两颗骰子，取较小点数，从牌墙末端数到对应墩（每墩 2 张），翻上面一张实物牌作为痞子，留在该位置明示。万、筒、条取同花色下一张作为癞子，9 循环到 1。字牌按东 → 南 → 西 → 北 → 中 → 发 → 白 → 东统一循环。
- **红中例外**：若直接翻到红中作痞子，或按下一张规则算出红中为癞子，均将一张实际白板换到骰子选中的位置作痞子、发财作癞子。原翻出的红中或北风回到白板原来的位置，保证 136 张牌及每种 4 张守恒；四张红中继续按单张杠规则处理。普通翻到白板仍按循环规则以东风作癞子。
- 痞子在发牌前翻出，不进入手牌、出牌或副露。每局都启用癞子：庄家仍为 14 张、闲家各 13 张，起手余牌为 82 张。
- **摸牌方向与剩余牌堆**：普通摸牌与起手发牌从墙头取；红中杠、痞子杠、明杠、暗杠、补杠后的补牌统一从墙尾取，并跳过已翻痞子。桌上四边各有 17 个固定墩位，每墩上下两张；剩余实牌逐张显示牌背，已经取走的位置留空，牌背总数严格等于顶栏「余牌」胶囊里的实时张数。青色「摸」标记指向墙头的下一张普通摸牌，金色「补」标记指向墙尾的下一张补牌；两颗骰子摆在牌桌正中央，取较小点数的那颗带金边，翻到的墩位在牌墙上标「痞·N」。痞子不计入余牌数，顶部痞子是同一实牌的展示，不额外计入牌数。

胡牌规则已确定如下，支持自摸和点炮：

- **屁胡**：四组顺子或刻子，加一对同花色、同点数的二、五、八作将。一张二五八实牌配一张癞子、两张癞子均可作将；其他实牌不能配一张癞子作将。
- **开口与癞子**：吃、碰、明杠算开口，补杠延续之前的碰；暗杠、红中单张杠、痞子单张杠不算开口。屁胡未开口可使用多个癞子，但只能自摸，不能接胡；开口后最多一个癞子，可以自摸或接胡。以胡牌暗手中参与判定的癞子计算；已经声明的普通副露使用实际牌面。
- **大胡**：七对、碰碰胡、将一色、风一色，均豁免二五八将和开口后的癞子数量上限，未开口也可接胡。七对仍须七组对子且无普通副露，四张同牌可计两对；碰碰胡须四组刻子或杠加一对，不能含吃牌。
- **将一色、风一色**：将一色的暗手与普通副露全部为二五八；风一色全部为东、南、西、北、中、发、白。两者只检查牌的范围，不要求四组加一对或七对的组合结构，胡牌张数仍须正确；癞子可替代该类牌，公开副露仍按真实牌面判断。红中及本局痞子在暗手中仍禁止胡牌。

吃上家、碰、明杠、暗杠、补杠与墙尾补牌继续沿用；吃碰杠使用真实牌面组合。抢牌优先级为胡 > 碰 / 杠 > 吃；同优先级取出牌者之后最近的一家。

当前采用**演示计分，尚未定稿**：基础 10；七对、碰碰胡、自摸各加 10，清一色加 20，字一色加 30。自摸其余三家各付一份，点炮一家付三份。杠暂不额外计分，也未增加红中专属番分。金币仅是本房间对局积分，没有充值或支付功能。

本次新增的大胡判定用于决定能否胡牌，未自行制定将一色、风一色的新番分；已有演示加分仍按原来的天然成牌条件计算，清一色加分不代表它获得本次大胡豁免。

不包含国标番数、抢杠胡、一炮多响、牌墙预留、四川血战或日式立直规则。不含账号、旁观或持久化排行榜。

## 文件

- `index.html`：分层页面结构与对话框。
- `styles.css`：深墨绿 / 烫金配色、通用控件与入口基础样式。
- `landscape.css` / `src/ui/orientation.js`：由房间状态和路由驱动的统一横屏对局舞台、固定牌河网格，以及手机横屏锁定与旋转引导。
- `table-depth.css`：胡桃木桌沿、金色嵌线、凹入式绿色台呢与桌体厚度。
- `tiles-depth.css`：象牙色牌面倒角、绿色牌体、侧边厚度和接触阴影。
- `seats-layout.css`：传统上下左右四方座位、居中牌桌与顶部金币栏。
- `laizi.css`：翻痞定癞玩法的痞子 / 癞子明示区及牌面角标。
- `wall-layout.css` / `src/network/wall-view.js`：四边完整剩余牌堆、实时张数、双骰、原位翻痞与头尾摸补牌标记；隐藏牌只渲染牌背。
- `rooms.css`：好友房创建、邀请、加入、准备与连接状态样式。
- `app.js`：交互、渲染、提示、声音及个人设置。
- `server.js`：同源 HTTP / SSE 房间接口、语音信令与静态文件服务。
- `src/server/rooms.js`：房间、座位、身份、人机管理与调度、服务器权威牌局及暗手隔离；四家公开副露和红中／痞子杠记录随快照同步。
- `src/server/voice.js`：从环境变量生成 STUN/TURN 配置，支持 coturn 短期凭证。
- `src/network/client.js`：房间请求、状态订阅、原标签页身份恢复、语音信令通道。
- `src/network/voice.js`：浏览器端 WebRTC 语音管理器，负责麦克风、P2P 连接、静音与说话检测。
- `engine.js`：麻将规则、牌局状态机及人机决策，独立于界面；好友房的人机由服务器调用原有决策策略。
- `src/domain/tile.js`：牌码、花色、点数及编码转换的唯一权威。
- `src/domain/model.js`：玩家、阶段、动作、副露及结算的 JSDoc 判别联合。
- `src/domain/invariants.js`：实牌守恒、红中胡牌限制与阶段迁移断言。
- `jsconfig.json`：对引擎与领域模块启用严格的编辑器类型检查，不参与运行。
- `assets/tiles.svg`：按实体麻将参考图重绘的 34 种 SVG 牌面：深蓝数字配红「萬」、三色筒子、鸟形一索、折线八索及细双框白板；文字均为矢量路径。编码仍为万 → 筒 → 条 → 字牌。
- `assets/avatar-player.svg` / `.png`：原创红顶瓜皮帽、朱红衫地主半身头像，512×512 白底，SVG 可编辑。
- `assets/avatar-1.svg` 至 `avatar-3.svg`：其他座位的默认头像。
- `docs/设计规格.md`：当前布局、UI 分层、材质与素材规格。
- `docs/联机部署.md`：公网、HTTPS、环境变量、Docker 与单实例运行约定。
- `deploy/`：阿里云部署脚本与说明——`install.sh` 一键安装、`update.ps1` / `更新到服务器.cmd` 一键更新、`Caddyfile.example` 域名反代示例、`turnserver.conf.example` coturn 语音中继配置、`部署到阿里云轻量.md` 全流程文档。
- `Dockerfile` / `.dockerignore`：零安装步骤的容器运行配置。

## 验证

```sh
npm test
```

规则测试涵盖胡牌分解、七对、牌数守恒、摸打、吃碰杠、单张红中杠、痞子单张杠、轮庄、翻痞子与癞子、抢牌优先级、玩家响应等待、随机种子复现、完整对局及积分延续。`npm test` 也包含好友房接口测试和语音测试，覆盖 STUN/TURN 配置、语音在线状态、SDP/ICE 信令定向转发、非法信令拒绝以及断线后语音状态清理；可用 `npm run test:online` 单独运行好友房接口测试。

`npm run test:ui` 执行四人独立浏览器的好友房用例，会自行启动测试服务器，覆盖创建、加入、准备、状态同步和刷新恢复；开发机需要已有 Playwright 与浏览器，运行游戏无需这些工具。

`npm run test:ui:layout` 验证手机与 PC 的满牌河、最大副露、操作热区及出牌动画后的稳定性；`npm run test:ui:orientation` 验证竖屏创建／等待、状态与路由切换、手机方向锁定与旋转提示，以及 PC 的统一横屏画布。旧单机竖屏布局测试已删除。

`npm run test:ui:hud` 验证创建房间同步请求全屏、反复进出和失败降级、刷新恢复，以及数字固定占位和 1–14 张暗手在有无副露时持续居中。

`node tests/ui-bots.mjs` 验证房主添加与移除人机、真人与人机混合开局及服务器自动操作；使用相同的本地浏览器测试环境。

`npm run test:ui:wall` 验证四种屏幕尺寸下的完整牌墙、逐张余牌同步、原位痞子、头尾摸补位置和联机同步；使用相同的本地浏览器测试环境。

`npm run test:ui:melds` 验证四人浏览器中的公开牌：真实点击红中杠、痞子杠、吃、碰、明杠、暗杠、补杠，逐一比对四个相对座位的牌面。另用 136 张守恒的显示夹具，覆盖四种尺寸下最多公开副露、四张红中加三张痞子杠且仍有完整 14 张暗手的布局，以及选牌和重复快照不重建牌面。夹具用于覆盖边界，不代表自然发出的完整对局。

`npm run test:ui:rules` 用四个真实浏览器验证普通胡的二五八将、开口癞子上限、未开口屁胡仅限自摸及四种大胡豁免。合法牌实际点击胡牌，四端同步结算并显示胡牌类型；非法牌的胡牌按钮隐藏，伪造请求由服务器拒绝且状态不变。测试夹具逐张分配真实 136 张牌。

`npm run test:ui:reveal` 验证自摸与接胡后四家原位亮牌、各观察者牌面一致、结算刷新重连、下一局恢复隐藏及流局保持原展示，并覆盖四种屏幕尺寸。`test:ui:bots` 另验证实际人机整局结束后的亮牌。

`npm run test:ui:notices` 用四个浏览器实际执行吃、碰、五种杠与胡，验证四家对应座位彩字、抢牌优先级、自动消失、重复快照不重播、胡字跨刷新保留与下一局清空，并检查四种屏幕尺寸下不遮挡牌面或操作区。

`npm test` 也会运行领域迁移安全网；可单独执行 `node tests/domain-invariants.mjs`，复现 200 局普通／癞子随机合法动作与 8 局 AI 对局，另有单独记录的真实发牌闭口屁胡自摸场景，逐步检查实牌守恒，并比较日志、计分与牌局状态。冻结的旧引擎 `tests/fixtures/engine-before-domain.js` 保持原样并受 SHA256 保护；测试用 `tests/legacy-wall-oracle.mjs` 仅在内存中显式适配已确认的骰子翻痞、红中例外、墙尾补牌、痞子单张杠、二五八将、开口癞子限制、闭口屁胡仅限自摸与四种大胡，使用冻结的分解搜索与计分作为对照；不宣称本次修改后仍与未适配新规则的旧对局一致，浏览器游戏不加载测试代码。

## 视觉设计

入口和房间等待页采用竖屏结构；对局只维护一套横屏布局，手机与 PC 共用位置、比例和样式。舞台填满横屏可用区域，窄窗口保持至少 16:9 并居中，不依据宽高阈值切换布局。桌面采用真实第一人称透视：远端收窄、近端展开，木质桌框、台呢、牌墙、三家暗手与牌河共用桌面投影；自己的直立手牌位于下方，头像、顶栏与操作按钮保持清晰的点击区域。四家头像统一大小，顶栏保留金币、余牌、痞子癞子、连接状态与音效/设置，操作区位于牌桌右侧，玩法说明与返回房间收在设置中。

四家牌河各有 36 个固定格位，四周为手牌、副露及补牌标记保留空间。牌面保持 5:7 长宽比，从网格单元的可用宽、高取较小值确定尺寸，随桌面一起缩放；满牌时不滚动、不裁剪、不重叠，也不遮挡玩家信息及操作区。最新出牌仍在原牌位适度放大并原地缩回，动画层不改变网格。适配范围为手机竖屏创建/等待、横屏对局，以及 PC 桌面浏览器的横屏对局，不维护其他设备版式。

牌桌与麻将牌采用半立体材质：牌面有圆角倒边，绿色牌体在下侧和右侧露出厚度；选牌时增强悬空阴影。中央牌桌使用木质桌沿、金色嵌线、细织纹台呢和凹入式中控面板，光线统一从左上方照入。厚度绘制在原牌尺寸内，牌面保持正视，便于小屏识别与触摸。

头像和牌面均为手工绘制的原生 SVG，不是 AI 位图生成结果。无远程字体、素材、CDN 或安装依赖。素材随服务器提供；所有真人玩家需要持续连接同一房间服务器。
